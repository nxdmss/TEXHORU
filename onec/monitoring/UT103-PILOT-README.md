# TEXHORU ↔ 1С УТ 10.3: пилот изменения цен на сайте

**Статус:** код сайта и тестовый исходный модуль 1С; **не** установленная или проверенная в рабочей 1С интеграция. Внедрять сначала только в копии тестовой базы. Нельзя запускать на боевой базе до проверки всех пунктов ниже.

## Цель

Менеджер меняет **розничную цену** в карточке товара TEXHORU. Сайт сохраняет новую цену и атомарно создаёт сообщение в очереди 1С. Обработка 1С получает сообщение, сверяет GUID номенклатуры и предыдущую розничную цену, проводит документ `УстановкаЦенНоменклатуры`, читает новую цену и отправляет квитанцию. После квитанции статус сайта становится **Применено в 1С**.

**Это не мгновенное изменение в 1С.** 1С закрыта от входящих подключений; она должна *сама* запустить получение сообщений. В данной версии форма запускает это **по кнопке**. Фоновый запуск потребует отдельного регламентного задания/агента 1С.

## Проверенные метаданные пилотной УТ 10.3

- Документ `УстановкаЦенНоменклатуры`, табличные части `Товары` и `ТипыЦен`.
- Регистр сведений `ЦеныНоменклатуры`, чтение через `СрезПоследних`.
- Тип цены **Розничная** с кодом `000000002`. Проверь, что в конкретной базе код и способ расчёта совпадают. Пилот не меняет закупочные цены.
- Товары с несколькими характеристиками/розничными ценами запрещены, пока не передаётся однозначный GUID характеристики.

## Установка

1. В тестовой базе УТ 10.3 сделай копию внешней обработки (например, `TEXHORUКаталогApple.epf`). Оригинал не трогай.
2. В модуль формы копии вставь `UT103-PilotRetailPrices-FormModule.bsl`. Это **текст исходного кода**, не собранная EPF.
3. Выгрузи подходящие товары из тестовой 1С на сайт; проверь совпадение GUID и существующей розничной цены.
4. Привяжи к кнопке формы предварительный просмотр:
   `Сообщить(ПилотТЕХОРУВыбрать30("ХОСТ.ngrok-free.dev", КлючAPI));`
5. Убедись, что в списке только нужные товары. **Включение группы требует отдельного подтверждённого вызова:**
   `Сообщить(ПилотТЕХОРУВыбрать30("ХОСТ.ngrok-free.dev", КлючAPI, Истина));`
6. Открой TEXHORU → **Админка → Товары → Редактировать** у товара из этой группы. Измени поле «Цена, ₽» и сохрани.
7. В админке **1С** увидишь **Ожидает 1С**. Применённой цену пока не считать.
8. В тестовой 1С вызови:
   `Сообщить(ПилотТЕХОРУПолучитьЦены("ХОСТ.ngrok-free.dev", КлючAPI));`
9. Проверь проведённый документ и цену в регистре, затем в админке **1С** нажми **Обновить статус**. При подтверждении увидишь **Применено в 1С**.

Старая функция `ПилотТЕХОРУВыбрать10` сохранена как совместимый псевдоним новой функции. Теперь выбирается **до 30** товаров без ограничения по бренду, **но только из существующей номенклатуры с точно совпадающей розничной ценой**. Список до подтверждения всегда показывается. Получение цены по-прежнему обрабатывает **не более 10 сообщений за вызов**.

## Защита от потери денег и рассинхронизации

- Только явно выбранные GUID с `priceSyncEnabled=true`; невыбранный товар из 1С не даст поменять цену на сайте.
- 1С сверяет `expectedPrice`; при несовпадении не проводит документ и возвращает конфликт.
- Одновременно только одно неподтверждённое изменение на товар.
- Пока сообщение ожидает 1С, старый импорт каталога **не откатывает** только что введённую цену сайта.
- Каждое сообщение имеет постоянный `id`, повторная доставка безопасна. Неудачная квитанция оставляет сообщение в очереди.
- Цена сайта изменяется сразу; **цена 1С только после успешного проведения в агенте 1С**.
- Изменение цен у конкурента не запускает этот сценарий самостоятельно; необходимо отдельное подтверждение применения.
- Название, себестоимость, остаток не отправляются в 1С через этот канал.

## Контракт REST (все пути относительно `/api`)

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `integrations/1c/price-sync/scope` | Явно включить 1–30 GUID; ключ `x-1c-key` |
| GET | `integrations/1c/price-sync/scope` | Получить разрешённые товары |
| GET | `integrations/1c/price-sync/pending` | Получить до 10 изменений `id, oneCId, expectedPrice, targetPrice` |
| POST | `integrations/1c/price-sync/receipts` | Квитанции после проверки записи в 1С |
| PATCH | `admin/products/:id` | Редактирование цены в админке; требует права администратора |
| GET | `admin/integrations/1c/price-sync` | Статусы по товарам и последним 30 изменениям |

Ключ API **нельзя** отправлять в чат или коммитить в репозиторий. Перед внедрением в реальной УТ сверить объекты метаданных и точный способ проведения документа на одном тестовом товаре.
