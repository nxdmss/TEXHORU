# TEXHORU ↔ 1С УТ 10.3: пилот изменения розничных цен

**Статус:** код сайта и тестовый исходный модуль 1С; **не** установленная или проверенная в рабочей 1С интеграция. Внедрять сначала только в копии тестовой базы. Нельзя запускать на боевой базе до проверки всех пунктов ниже.

## Два сценария

### 1. Цена из парсера 05.ru

1. Парсер собирает предложения и не меняет цены автоматически.
2. Менеджер открывает **Админка → Обновление цен**.
3. Отмечает отдельные товары или нажимает **«Выбрать все»**.
4. Нажимает **«Обновить выбранные в 1С»**. Только выбранные строки попадают в очередь.
5. Агент 1С получает очередь, сверяет GUID и ожидаемую розничную цену, проводит документ `УстановкаЦенНоменклатуры` и отправляет квитанцию.
6. TEXHORU меняет цену на сайте **только после успешной квитанции 1С**. До этого на витрине остаётся старая цена.

### 2. Ручное изменение цены в карточке сайта

Администратор может изменить цену в карточке товара, заранее включённого в область обмена. Сайт сохраняет цену и создаёт сообщение в очереди 1С. Для этого старого ручного сценария сайт показывает новую цену сразу, а статус 1С остаётся ожидающим до квитанции.

**Это не мгновенное изменение в 1С.** 1С закрыта от входящих подключений; она должна сама запустить получение сообщений. В текущей версии форма/агент запускает это по кнопке. Фоновый запуск требует отдельного регламентного задания.

## Проверенные метаданные пилотной УТ 10.3

- Документ `УстановкаЦенНоменклатуры`, табличные части `Товары` и `ТипыЦен`.
- Регистр сведений `ЦеныНоменклатуры`, чтение через `СрезПоследних`.
- Тип цены **Розничная** с кодом `000000002`. Проверь, что в конкретной базе код и способ расчёта совпадают. Пилот не меняет закупочные цены.
- Товары с несколькими характеристиками/розничными ценами запрещены, пока не передаётся однозначный GUID характеристики.

## Установка

1. В тестовой базе УТ 10.3 сделай копию внешней обработки. Оригинал не трогай.
2. В модуль формы копии вставь `UT103-PilotRetailPrices-FormModule.bsl`. Это **текст исходного кода**, не собранная EPF.
3. Выгрузи подходящие товары из тестовой 1С на сайт; проверь совпадение GUID и существующей розничной цены.
4. Привяжи к кнопке формы предварительный просмотр:
   `Сообщить(ПилотТЕХОРУВыбрать30("ХОСТ.ngrok-free.dev", КлючAPI));`
5. Убедись, что в списке только нужные товары. **Включение группы требует отдельного подтверждённого вызова:**
   `Сообщить(ПилотТЕХОРУВыбрать30("ХОСТ.ngrok-free.dev", КлючAPI, Истина));`
6. В TEXHORU открой **Админка → Обновление цен**, выбери нужные предложения и нажми **«Обновить выбранные в 1С»**.
7. В тестовой 1С вызови:
   `Сообщить(ПилотТЕХОРУПолучитьЦены("ХОСТ.ngrok-free.dev", КлючAPI));`
8. Проверь проведённый документ и цену в регистре. После успешной квитанции цена на сайте обновится, а в админке **1С** появится статус **«Цена обновлена в 1С»**.

Старая функция `ПилотТЕХОРУВыбрать10` сохранена как совместимый псевдоним новой функции. Теперь выбирается **до 30** товаров без ограничения по бренду, но только из существующей номенклатуры с точно совпадающей розничной ценой. Список до подтверждения всегда показывается. Получение цены обрабатывает не более 10 сообщений за вызов.

## Защита от потери денег и рассинхронизации

- Только явно выбранные GUID с `priceSyncEnabled=true`; невыбранный товар из 1С не попадёт в очередь.
- Парсер и автопроверка никогда сами не меняют цену сайта или 1С.
- 1С сверяет `expectedPrice`; при несовпадении не проводит документ и возвращает конфликт.
- Одновременно только одно неподтверждённое изменение на товар.
- Для предложений парсера сайт сохраняет прежнюю цену до успешной квитанции 1С.
- Старый импорт каталога не должен затирать цену, пока сообщение ожидает подтверждения.
- Каждое сообщение имеет постоянный `id`; повторная доставка безопасна. Неудачная квитанция оставляет сообщение в очереди.
- Ручная правка карточки сайта по-прежнему показывает цену сразу; подтверждение 1С отображается отдельно.
- Изменение цен у конкурента не запускает обновление само по себе: нужно выбрать товары и нажать кнопку.
- Название, себестоимость и остаток не отправляются в 1С через этот канал.

## Контракт REST (все пути относительно `/api`)

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `integrations/1c/price-sync/scope` | Явно включить 1–30 GUID; ключ `x-1c-key` |
| GET | `integrations/1c/price-sync/scope` | Получить разрешённые товары |
| GET | `integrations/1c/price-sync/pending` | Получить до 10 изменений `id, oneCId, expectedPrice, targetPrice` |
| POST | `integrations/1c/price-sync/receipts` | Квитанции после проверки записи в 1С |
| PATCH | `admin/products/:id` | Ручное редактирование цены в админке |
| GET | `admin/integrations/1c/price-sync` | Статусы по товарам и последним 30 изменениям |

Ключ API **нельзя** отправлять в чат или коммитить в репозиторий. Перед внедрением в рабочей УТ сверить объекты метаданных и способ проведения документа на одном тестовом товаре.
