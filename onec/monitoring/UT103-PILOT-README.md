# TEXHORU ↔ 1С УТ 10.3: пилот 10 iPhone 13 (TEST)

**Статус:** исходный код 1С для внедрения и проверки в тестовой базе; не готовая `.epf`, не проверенная в живой 1С интеграция. Сайт/API имеют автоматические тесты, но поведение типовой конфигурации зависит от версии УТ и регистров. Боевую `base` не использовать.

## Что проверено по скриншотам тестовой УТ

- `Документ.УстановкаЦенНоменклатуры`; табличные части `Товары` и `ТипыЦен`.
- `Товары`: `Номенклатура`, `ХарактеристикаНоменклатуры`, `Цена`, `Валюта`, `ЕдиницаИзмерения`, `ТипЦен`, `ИндексСтрокиТаблицыЦен`.
- `Справочник.ТипыЦенНоменклатуры`: `Розничная`, код `000000002`, RUB, базовая `Закупочная`, наценка 15%, округление 50 ₽.
- `РегистрСведений.ЦеныНоменклатуры` имеется, но точный результат запроса `СрезПоследних` и проведение документа ещё требуют теста.

## Для вставки в внешнюю обработку

1. Создать копию **рабочей** внешней обработки `TEXHORUКаталогApple.epf` на удалённом ПК (не изменять оригинал). Открыть копию в конфигураторе тестовой базы.
2. Открыть модуль формы и добавить код из [UT103-PilotRetailPrices-FormModule.bsl](./UT103-PilotRetailPrices-FormModule.bsl). Это **текстовый модуль**, не готовый файл EPF. Сохранить как новую EPF, проверить синтаксис.
3. Для подготовки списка выполнить из формы (где `КлючAPI` уже задан):
   `Сообщить(ПилотТЕХОРУВыбрать10("ХОСТ.ngrok-free.dev", КлючAPI));`
   Будут выбраны 10 уже импортированных на сайт iPhone 13 с совпадающими текущими розничными ценами. На этом шаге данные **не меняются**.
4. Проверить все десять позиций и включить пилот явно:
   `Сообщить(ПилотТЕХОРУВыбрать10("ХОСТ.ngrok-free.dev", КлючAPI, Истина));`
5. Для получения подтверждённых изменённых цен после нажатия «Применить» в админке:
   `Сообщить(ПилотТЕХОРУПолучитьЦены("ХОСТ.ngrok-free.dev", КлючAPI));`
6. В тестовой 1С проверить появление проведённого `УстановкаЦенНоменклатуры`, сумму в `ЦеныНоменклатуры` и квитанцию в админке TEXHORU → **1С**.

Функции `ПилотТЕХОРУВыбрать10` и `ПилотТЕХОРУПолучитьЦены` нужно привязать к **новым кнопкам копии формы** или временно вызвать из процедуры формы вручную; они не вызываются сами при установке файла. Ключ API не отправлять в чат и не сохранять в Git.

## Правила записи и защита

- Только `1С test`; только 10 заранее разрешённых GUID; только номенклатура iPhone 13; только `Розничная` код `000000002`.
- Перед записью проверяется `expectedPrice` из очереди TEXHORU против текущей цены 1С; если другая — документ **не проводится**, возвращается ошибка конфликта.
- Когда цена уже равна `targetPrice`, повторно документ не создаётся; квитанция может быть отправлена снова.
- Если у номенклатуры несколько характеристик с разными ценами, операция блокируется — требуется конкретная характеристика/вторая версия контракта.
- После проведения цена перечитывается из регистра; при несовпадении транзакция отменяется.
- На сайте ошибки передачи остаются в очереди для повторной попытки, а не исчезают.
- Тип цены расчётный (15% от закупочной, шаг 50 ₽). В тесте нужно обязательно проверить, что ручной документ сохраняет нужное значение; проведение может потребовать заполнения дополнительных реквизитов конкретной версии УТ.

## Что ещё нужно до «полностью бесшовно»

1. **Экспорт из 1С → TEXHORU** должен отправлять свежую розничную цену выбранных 10 номенклатур (существующая Apple-обработка сейчас выполняется вручную).
2. **Сайт → 1С** должен запускать `ПилотТЕХОРУПолучитьЦены` автоматически по расписанию в доступном процессе 1С (либо через разрешённый агент). Пока код использует ручной вызов.
3. Выполнить живой end-to-end тест по одному товару и проверить отражение цены после закрытия/перезапуска 1С, затем масштабировать на десять.

Не подменять эти пункты обещанием полной автоматизации: серверная очередь сама не изменяет базу 1С, пока 1С-агент её не забрал.
