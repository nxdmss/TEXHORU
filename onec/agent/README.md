# Автоматический агент TEXHORU для тестовой 1С

Агент забирает из TEXHORU только уже подтверждённые сотрудником изменения цен. Он запускает 1С по расписанию, выполняет одну проверку очереди и закрывает сеанс. Вручную открывать обработку каждый раз не нужно.

**Состояние:** исходный код агента и установщик подготовлены. Готовый файл `.epf` ещё нужно один раз собрать в конфигураторе 1С и проверить на копии УТ 10.3. Этот репозиторий не содержит собранного файла обработки.

## Как это работает

1. Сотрудник выбирает товары на сайте и подтверждает отправку.
2. Планировщик Windows раз в две минуты проверяет очередь.
3. Если очередь пуста, 1С не запускается.
4. Если есть изменения, Windows запускает 1С в скрытом режиме с обработкой `TEXHORU-Agent.epf`.
5. Обработка сверяет GUID и текущую розничную цену, создаёт и проводит документ `УстановкаЦенНоменклатуры`.
6. Только после проверки записанной цены обработка отправляет квитанцию сайту.
7. 1С закрывает сеанс. Результат виден в разделе «Обмен с 1С».

Планировщик работает, пока пользователь, установивший агента, вошёл в Windows. Для первого варианта это обычная задача Windows, а не постоянная служба.

## Что программист должен собрать один раз

Нужна тестовая копия **1С:Управление торговлей 10.3** и установленная платформа 1С.

1. Открой конфигуратор именно тестовой копии.
2. Создай внешнюю обработку.
3. Добавь основную обычную форму (тип формы «Обычная»).
4. Открой модуль этой формы и замени его содержимое целиком файлом [UT103-PilotRetailPrices-FormModule.bsl](../monitoring/UT103-PilotRetailPrices-FormModule.bsl).
5. У основной формы назначь обработчик события **ПриОткрытии** с именем `ПриОткрытии`. Для этого открой свойства формы, найди событие «ПриОткрытии» и выбери одноимённую процедуру модуля.
6. Проверь модуль на ошибки компиляции в конфигураторе.
7. Сохрани внешнюю обработку как `TEXHORU-Agent.epf`.

Это разовая работа программиста. После сборки сотруднику не нужно вручную открывать EPF: планировщик запускает его сам.

**Не вставляй модуль в рабочую базу.** Не подключай агент к рабочей базе. Обработка использует объекты УТ 10.3 и должна сначала пройти проверку на копии.

## Настройка тестового сервера TEXHORU

В `server/.env.local` тестового экземпляра должны быть заданы:

```dotenv
ONE_C_BASE_KIND=TEST
ONE_C_TEST_PRICE_SYNC_ENABLED=true
ONE_C_TEST_AUTO_PRICE_SCOPE=false
ONE_C_API_KEY=отдельный-длинный-ключ-только-для-тестовой-связи
```

После изменения настроек перезапусти сервер TEXHORU.

- `ONE_C_BASE_KIND=TEST` помечает экземпляр как тестовый.
- `ONE_C_TEST_PRICE_SYNC_ENABLED=true` открывает обратный обмен ценами только на тестовом экземпляре.
- `ONE_C_TEST_AUTO_PRICE_SCOPE=false` оставляет автоматическое добавление товаров в разрешённую группу выключенным. Это не мешает отправлять вручную выбранные и заранее разрешённые товары.
- `ONE_C_API_KEY` должен быть отдельным ключом тестового экземпляра. Не используй ключ рабочей 1С.

Сервер блокирует чтение очереди, изменение разрешённой группы и отправку квитанций, если одновременно не выставлены `ONE_C_BASE_KIND=TEST` и `ONE_C_TEST_PRICE_SYNC_ENABLED=true`.

## Установка на Windows

Скопируй папку `onec/agent` из репозитория на компьютер, где запускается тестовая 1С. В ней должны находиться три файла:

- `Install-TEXHORUAgent.ps1`
- `Run-TEXHORUAgent.ps1`
- `Remove-TEXHORUAgent.ps1`

Открой PowerShell в этой папке и запусти:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\Install-TEXHORUAgent.ps1
```

Установщик спросит:

- название тестовой базы; в нём должно быть слово «Тест», «Копия», «Пилот» или TEST;
- файловая это база или серверная;
- путь к платформе `1cv8.exe`;
- путь к собранному `TEXHORU-Agent.epf`;
- способ входа в 1С;
- HTTPS-адрес тестового сайта;
- ключ `ONE_C_API_KEY` тестового сервера.

Перед установкой нужно вручную подтвердить фразой `ПОДТВЕРЖДАЮ ТЕСТ`, что выбрана именно тестовая база. Название без признака тестовой копии установщик не принимает.

Пароль 1С и ключ API сохраняются в зашифрованном Windows виде для текущей учётной записи. Временный файл с ключом существует только на время одного запуска и находится в папке с ограниченным доступом. Если используется пароль 1С, он кратковременно передаётся процессу 1С при запуске; для постоянной работы лучше использовать отдельного пользователя с минимальными правами или вход Windows, если он настроен.

После установки задача **TEXHORU 1C Test Agent** проверяет очередь каждые две минуты, пока пользователь вошёл в Windows. Установщик предложит выполнить первую проверку сразу.

## Обновление и демонстрация

Для существующего агента не нужно повторно вводить ключи: используй `Update-TEXHORUAgent.ps1 -EpfPath 'C:\путь\TEXHORU-Agent.epf'`. Новый EPF нужно предварительно собрать из актуального BSL. Обновление делает резервную копию, сохраняет настройки и включает автоматическую задачу после входа в Windows. Порядок: [демонстрация через ngrok](../../docs/demo-ngrok.md).

## Где смотреть результат

Папка агента:

`%LOCALAPPDATA%\TEXHORU\Agent`

- `agent.log` — результат каждого запуска и ошибки.
- `1c-output-<id>.log` — сообщения платформы 1С.
- `agent-result-<id>.txt` — результат последней обработки.
- `agent-config.json` — зашифрованные настройки. Не отправляй этот файл другим людям.

На сайте открой **Управление магазином → Обмен с 1С**. Успешный результат должен получить статус **«Выполнено»**.

Если появилась ошибка, не нажимай отправку повторно. Сначала посмотри журнал агента и причину в админке.

## Остановка и удаление

Остановить автоматический запуск, сохранив журнал и настройки:

```powershell
.\Remove-TEXHORUAgent.ps1
```

Удалить также настройки и журнал можно отдельным подтверждённым действием:

```powershell
.\Remove-TEXHORUAgent.ps1 -Purge
```

Это не удаляет базу 1С и данные магазина.

`agent-result-<id>.txt` содержит JSON протокола 2: `ok`, `applied`, `failed`, `processed`, `batches`. Старое «обработано изменений» больше не считается доказательством успеха. Сохраняются последние 20 журналов каждого вида, временный файл с ключом удаляется после сеанса. В разделе «Обмен с 1С» автоматически обновляются связь с агентом и результаты операций.

## Ограничения первого запуска

- Агент обрабатывает до 30 изменений за один запуск, пакетами по 10. При ошибке дальнейшие пакеты останавливаются, а повтор откладывается.
- Одновременно работает только один экземпляр агента.
- Если текущая цена 1С отличается от ожидаемой, товар не проводится; причина уходит в квитанцию.
- Если у товара несколько характеристик и нельзя однозначно выбрать нужную, изменение блокируется.
- Используется только тип цены «Розничная» с проверкой кода и названия.
- Автоматический выбор новых товаров не включён.
- Агент не предназначен для рабочей базы.

До реального испытания в конкретной тестовой УТ 10.3 нельзя считать сборку EPF и проведение документа проверенными.
