# Передача TEXHORU другому программисту

## Что это за проект

TEXHORU — магазин электроники и служебная панель управления. Каталог приходит из 1С. Сайт проверяет цены на 05.ru и предлагает новые розничные цены. Решение об отправке принимает сотрудник; проведение в 1С должен подтвердить отдельный агент.

**Внимание:** проект нельзя объявлять готовым к работе с продуктивной 1С без испытаний. Тестовый агент в отдельной разработке; сборка `.epf` и проверка реальной установки требуют Windows и конкретной базы.

## С чего начать

1. Прочитать [главную страницу](../README.md) и [сценарий цен](как-работать-с-ценами.md).
2. Поставить Node.js 22 или новее.
3. Скопировать `server/.env.example` в `server/.env.local`, задать собственные ключи. Секреты от действующего сервера не нужны для локального запуска.
4. Выполнить в корне проекта:

```bash
npm ci
npm --prefix server ci
npm run db:local:generate
npm run db:local:push
npm run dev
```

5. Проверить http://127.0.0.1:5173 и http://127.0.0.1:3000/api/health.
6. Перед сдачей изменений выполнить:

```bash
npm run build:all
npm --prefix server run test:monitor
```

Приложение использует React и TypeScript для страниц, NestJS для сервера, Prisma и SQLite для локальной базы. Названия файлов и классов оставлены прежними, чтобы не ломать совместимость и тесты.

## Два разных обмена, которые нельзя путать

**1С → TEXHORU:** товары, цены и остатки. Это загрузка каталога, а не разрешение писать цены обратно.

**TEXHORU → 1С:** только вручную одобренные изменения розничной цены. Сначала создаётся запись об отправке, агент читает её и возвращает результат. Пока нет подтверждения 1С, цена витрины не меняется.

Есть также отдельная очередь *наблюдений конкурента*. Это данные для истории, не документ изменения розничных цен. Их нельзя смешивать.

## Что готово и что проверить

- Каталог, оформление заказа, интерфейс управления — реализованы.
- Парсер 05.ru, поиск совпадений, проверка цен и история — реализованы, требуют проверки на работающем сервере с доступом к 05.ru.
- Предложение: **05.ru минус 100 ₽**, без себестоимости. Ограничение изменения более 10% сохраняется.
- Выбор товаров, очередь цен, серверная проверка и подтверждение — реализованы.
- Автодопуск импортированных товаров тестовой 1С выключен по умолчанию. Его настройки: `ONE_C_BASE_KIND=TEST` и `ONE_C_TEST_AUTO_PRICE_SCOPE=true`. Максимум 30 товаров; не включать для рабочей базы.
- Реальное автоматическое проведение цен агентом УТ 10.3 **не подтверждено**. Работа над агентом обсуждается в [PR №37](https://github.com/nxdmss/TEXHORU/pull/37). Проверять только в тестовой 1С.

## Перед изменениями и запуском

- **Не выкладывать** `.env.local`, базы данных, пароли, архивы с данными магазина и ключи 1С.
- **Не выполнять** `TEXHORU-RESET.cmd` при обычном обновлении. Это отдельная команда для осознанного сброса данных.
- Перед обновлением работающего проекта сделать копии `server/prisma/dev-local.db`, `server/uploads/` и настроек.
- Не изменять формат ответа 1С и имена полей без согласования: уже созданные обработки будут отправлять старый формат.
- Не убирать проверку GUID, допуск TEST, подтверждение действия и квитанцию от 1С.
- Не включать производственную запись в 1С в рамках косметических изменений.

## Как передавать изменения

1. Создать отдельную ветку.
2. Сделать одно понятное исправление.
3. Проверить сборку и тесты.
4. Открыть запрос на объединение; написать простыми словами, что изменилось, как проверить и какие есть риски.
5. После просмотра объединить с `main`.

Подробные прежние материалы сохранены в [списке документации](README.md). Они нужны для поиска технических деталей, но не обязательны для первого знакомства.
