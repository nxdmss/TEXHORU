# Интерфейс TEXHORU

Магазин и админка используют общие переменные `--tx-*` из `src/brand-system.css`: светлая бумага, белые поверхности, чёрный текст и красный акцент. Основные действия имеют явную подпись; зелёный, синий и янтарный используются только для состояния. Базовое скругление — 8 px, без градиентов и постоянной анимации.

`brand-system.css` задаёт магазин, карточки, корзину и оформление. `admin-control.css` использует те же переменные для панели управления, сохраняя три группы готовности и свёрнутые связи с 05.ru. Шапка магазина на телефоне делится на строку логотипа/действий и строку каталога/поиска.

Корзина — отдельный диалог `CartDrawer`: Escape, удержание фокуса, возврат фокуса после закрытия, блокировка фоновой прокрутки, явное удаление. Фотографии и цены одинаковы в каталоге, корзине и заказе. Количество сверяется с доступным остатком из API; сервер повторно проверяет наличие и стоимость при оформлении. Нет в наличии и предзаказ — разные состояния.

Проверка сохранённых цен 05.ru показывает очередь, прогресс и итог прямо под своей кнопкой. Последняя задача возвращается вместе с готовностью товаров и сохраняется после обновления страницы. Ошибку запуска браузера, ограничения доступа и частичные ошибки нельзя заменять молчаливым возвратом кнопки или общей подписью об устаревшей цене. Подробности раскрываются отдельно; готовность к отправке в 1С определяется прежними проверками.

Повтор оформления после потери ответа использует тот же ключ операции, пока данные заказа не изменились. Ненастроенная онлайн-оплата не предлагается. Комментарий и состав заказа можно свернуть; технические адреса и инструкции по запуску сервера не показываются покупателю.

Проверка после сборки:

```bash
npm run build:all
node tests/storefront.browser.mjs
node tests/price-demo.browser.mjs
```

Первый браузерный сценарий проверяет 1440/768/390/320 px, поиск с Enter, фильтр брендов, корзину, остаток, клавиатуру, повтор запроса и настоящий заказ в изолированной SQLite. Второй проверяет админку, автоматическое подключение импорта и поиск по выбранным товарам; ответы процесса обмена моделируются. Ни один сценарий не обращается к рабочей 1С. В Linux CI оба запускаются автоматически.

Фото товаров используют общий `ProductImage` в каталоге, карточке, корзине, заказе и редакторе. Прозрачные поля PNG/WEBP/AVIF определяются по альфа-каналу при первом чтении URL; границы кэшируются в памяти, исходные файлы и прозрачность сохраняются. Изображение вписывается без растяжения и обрезки товара. Для iPhone 12–17 высота корпуса задаёт относительный масштаб: цвета и память одной модели одинаковы, Pro Max крупнее. Остальные товары занимают доступную область с сохранением пропорций. Для сравнимого вида загружайте один товар в одинаковом ракурсе; белый фон JPG автоматически не удаляется. Внешние фото без доступа CORS безопасно вписываются по полному кадру.
