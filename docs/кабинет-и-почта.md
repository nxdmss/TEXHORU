# Кабинет покупателя и письма TEXHORU

Покупатель открывает **Кабинет** в шапке магазина. Регистрация создаёт только роль покупателя. После подтверждения почты доступны текущие заказы, история покупок, имя, телефон и адрес для следующего оформления.

## Что работает

- Регистрация, вход, выход, повтор письма, подтверждение адреса и восстановление пароля.
- HTML-письмо в стиле магазина и текстовая версия для почтовых клиентов.
- Одноразовая ссылка подтверждения на 24 часа, сброса пароля — на 30 минут.
- Токены в базе хранятся как SHA-256; пароль — bcrypt. Ссылка открывает форму, а действие выполняется явной кнопкой. Почтовые сканеры не расходуют ссылку обычным GET-запросом.
- Токен передаётся во фрагменте ссылки `#…`, не в HTTP-пути или query; после открытия форма убирает его из адресной строки.
- После смены пароля старые сессии прекращают работать. Сессия покупателя хранится в HttpOnly-cookie на 8 часов; в production — только HTTPS. Отдельная cookie сотрудников сохраняется.
- Ограничены число попыток входа и отправка писем. На один адрес/тип письма — не чаще раза в минуту. При отсутствии SMTP интерфейс прямо сообщает, что письма ещё не подключены.
- В кабинет попадают только заказы, оформленные после входа в этот аккаунт. Введённый при гостевом заказе email не даёт доступа к истории. Гостевой заказ доступен по своей персональной ссылке.
- В кабинете выводятся последние 100 заказов; все заказы сохраняются в базе.

## Настройка на сервере Яндекс Cloud

В `/etc/texhoru/app.env` добавьте через редактор сервера (секреты не пересылайте в чат и не коммитьте):

```dotenv
SMTP_HOST=smtp.example.ru
SMTP_PORT=465
SMTP_USER=account@your-domain.ru
SMTP_PASSWORD=APP_PASSWORD_FROM_MAIL_PROVIDER
MAIL_FROM=TEXHORU <account@your-domain.ru>
```

Пример — шаблон, не действующие настройки. Используйте домен магазина и пароль приложения/SMTP-ключ выбранного провайдера. Порт **465** использует TLS сразу; **587** требует STARTTLS. Проверка сертификата включена. Отправитель должен быть разрешён у провайдера.

`FRONTEND_PUBLIC_URL` должен указывать на настоящий HTTPS-адрес магазина. В облачной compose-конфигурации он задаётся из `TEXHORU_DOMAIN`. Для локальной разработки нужен адрес, открывающийся в вашем браузере, например `http://127.0.0.1:5173`.

После установки этой версии пересоздайте контейнер, чтобы прочитать изменённый env-файл:

```bash
sudo docker compose --env-file /etc/texhoru/compose.env -f /opt/texhoru/deploy/cloud/compose.yaml up -d --force-recreate --wait app
```

Если проект установлен в другой папке, укажите её путь. Обычный `docker restart` перечитать изменённый env-файл не может. В DNS домена настройте SPF, DKIM и DMARC по инструкции почтового провайдера и проверьте отправку на реальный почтовый ящик.

Тестовая регистрация должна пройти весь путь: письмо → подтверждение → вход → заказ → кабинет → сброс пароля. Автотест заменяет исходящую доставку тестовым транспортом; он не подтверждает доставляемость вашей почты.

## Обновление базы

Обе Prisma-схемы обновлены одинаково. Облачный запуск применяет новые таблицы/поля через существующий `deploy/cloud/init.mjs` без сброса данных. Для локального запуска выполните генерацию Prisma и `db:local:push`. Перед обновлением действующего магазина сохраните обычную резервную копию базы, uploads и настроек.

## Проверки

```bash
npm run build:all
node --test server/tests/account-catalog-sync.test.cjs
node tests/accounts.browser.cjs
```

Браузерный тест использует отдельную временную SQLite-базу, подменяет только отправку почты и удаляет базу после завершения. Снимки экранов сохраняются в `work/screenshots/`. Проверены ширины 1440, 390 и 320 px, регистрация и подтверждение, вход, сохранение профиля, заполнение заказа из профиля, реальная принадлежность заказа и восстановление доступа.
