# TEXHORU: мониторинг 05.ru и учебная 1С на Windows

Обновление подготовлено для исходников `b07e9c06cdcd6047889a1d5ac99b8b92d1b6cd76`.
Твоя платформа со скрина: 1С:Предприятие 8.3, учебная версия 8.3.27.1508, файловая база TEXHORU TEST. Конфигурация на скрине называется просто «Конфигурация». Наличие справочника `Товары` и его реквизитов проверь в дереве Конфигуратора. Код рассчитан на учебную структуру из прежнего примера проекта; он не является расширением для УТ/УНФ/Розницы.

## Что готово и что ещё предстоит

В TEXHORU реализованы сбор карточек, обход наблюдаемой пагинации, сопоставление, подтверждение связей, история, расписание повторных проверок и очередь результатов для 1С. Есть файловый и прямой локальный HTTP-обмен.

В папке `onec/monitoring` лежат готовые тексты модулей 1С. Скомпилированных `.cf`, `.cfe` и `.epf` в пакете нет: без установленной платформы и точных метаданных твоей базы я не могу собрать и проверить их. Один раз создаём метаданные и вставляем файлы в модули по инструкции ниже. После этого кнопки обмена работают без ручного написания кода.

Визуально проверена реальная карточка iPhone на 05.ru и пагинация раздела «Телефоны и гаджеты». В этой среде локальный Chromium не запустился; прямой запуск всего Playwright-парсера на Windows нужно проверить первым тестом. Фикстура теста записана с реально открытой карточки, цена в ней историческая, а не обещание актуальной цены.

## 1. Запустить TEXHORU одной кнопкой

1. Открой папку `TEXHORU` внутри нового архива и скопируй её содержимое в свою существующую папку TEXHORU с заменой файлов.
2. Нажми **TEXHORU.exe**. Если ещё открыта старая версия, сначала закрой её окно.
3. Первый запуск может занять несколько минут: приложение само подготовит зависимости и браузер, сохранит копию данных, обновит схему и откроет сайт.

Отдельный установщик и команды npm больше не нужны. Для остановки — **TEXHORU STOP.exe**. При повторном запуске подготовленная версия используется повторно.

Старую папку `node_modules` приложение не удаляет. Зависимости устанавливаются в локальный кеш вне OneDrive; рабочая база остаётся в исходной папке (`server/prisma/dev-local.db`), фотографии — в `server/uploads`. Перед изменением схемы сохраняется резервная копия в `backups/automatic-ДАТА`. Существующая учётная запись не пересоздаётся. Флаги сброса базы и разрешения потери данных не используются.

Первой подготовке нужен интернет. Если установленного Node.js 22+ нет, EXE загрузит переносимую версию с официального сайта и проверит контрольную сумму. При ошибке показывается путь `.texhoru/startup.log` — пришли этот файл или последние строки.

| `Категория` | Строка 100, для этой учебной базы | Смартфоны |
| `Цена` | Число 15,2; неотрицательное | 99990 — условная наша цена |
| `Остаток` | Число 10,0; неотрицательное | 5 |
| `Бренд` | Строка 100, желательно | Apple |
| `Себестоимость` | Число 15,2, желательно | 80000 — условный пример |
| `Модель` | Строка 100, желательно | iPhone 17 Pro |
| `Память` | Строка 30, желательно | 256 GB |
| `ОЗУ` | Строка 30, желательно | 12 GB |
| `Цвет` | Строка 100, желательно | Orange |
| `ТипSIM` | Строка 100, желательно | eSIM |

Чтобы добавить поле: открой справочник → **Данные → Реквизиты → Добавить**; введи имя ровно как в таблице и выбери тип. Если поле существует с другим типом, не меняй его вслепую — пришли скрин. Для базы работодателя эта структура будет другой: её нужно отдельно адаптировать.

## 3. Создать хранилище цен конкурента

В дереве **Регистры сведений → Добавить**:

- Синоним: `Мониторинг цен TEXHORU`.

## 4. Установить общий модуль

1. **Общие → Общие модули → Добавить**.
2. Имя: `ОбменTEXHORU` — без пробелов.
3. Свойство **Сервер**: включено. **Клиент (управляемое приложение)**, **Клиент (обычное приложение)**, **Глобальный**, **Вызов сервера**: выключены. Привилегированный режим не нужен.
4. Открой модуль. Открой файл `onec/monitoring/ExchangeTEXHORU.bsl` в Блокноте: **Ctrl+A → Ctrl+C**. В редакторе модуля 1С: **Ctrl+A → Ctrl+V**.
5. Сохрани. Проверь синтаксис модуля: **Ctrl+F7** либо пункт проверки синтаксиса в меню Конфигуратора. Если есть ошибка, пришли её вместе со строкой — проверка компиляции 1С здесь не выполнялась.

Этот модуль экспортирует весь непомеченный на удаление каталог, используя GUID ссылок товаров. Категории-строки применяются только в учебном варианте; в коммерческой базе нужны GUID справочника категорий и GUID характеристики/варианта номенклатуры, если вариант хранится отдельно.

Если пункт скрыт: настройки/параметры → включить режим технического специалиста. Альтернативно включи обработку в имеющуюся подсистему «Товары», обнови базу и открой её через команды этой подсистемы.
10. Регистр смотри там же: **Регистры сведений → Мониторинг цен TEXHORU**. Может понадобиться включить его в подсистему для удобного доступа.

## 6. Первый полный тест через файлы

1. В 1С создай один товар: **Apple iPhone 17 Pro 12GB/256GB Orange eSIM**. Заполни основные реквизиты; цены и себестоимость из таблицы выше являются условными тестовыми значениями.
2. В обработке нажми **Выгрузить каталог в JSON**. Появится `C:\TEXHORU-Exchange\catalog.json`.
3. В TEXHORU → **Мониторинг цен → Обмен с 1С → 1. Загрузить каталог из 1С** выбери `catalog.json`. У товара теперь есть `oneCId`, то есть GUID ссылки 1С.
4. В блоке **Одна карточка** оставь ссылку iPhone и нажми **Проверить цену**. При ошибке 403/429 проверка останавливается, последняя успешная цена сохраняется. Не запускай обход снова и снова: пришли текст ошибки.
5. В найденной карточке нажми **Сопоставить / история**, выбери свой товар, сверь модель, память, цвет и SIM и нажми **Подтвердить связь**. Если характеристики расходятся, подтверждение блокируется.
6. Нажми **Подготовить очередь для 1С**, затем **2. Скачать результаты JSON**. Сохрани файл как `C:\TEXHORU-Exchange\monitoring.json` (имя должно быть именно таким; убери суффикс `(1)`, если браузер его добавил).
7. В 1С нажми **Получить мониторинг из JSON**. Смотри регистр: должна появиться цена конкурента, ссылка, дата и наличие, а наша цена в `Товары` остаётся прежней.
8. В TEXHORU выбери **3. Загрузить подтверждения 1С**, укажи `C:\TEXHORU-Exchange\receipts.json`. Статус станет **Сохранено в 1С**. При ошибке сохранения результат останется в очереди; причина попадёт в журнал обмена.
9. Загрузив тот же `monitoring.json` ещё раз, убедись, что в регистре не появилась вторая строка с тем же `СообщениеID`.

Это тест полного цикла, а не импорт товаров конкурента в реальный ассортимент работодателя.

## 7. Перейти к прямому локальному обмену

1. TEXHORU и 1С должны работать на одном Windows-компьютере. TEXHORU backend: `127.0.0.1:3000`.
2. Открой `server/.env.local` в Блокноте, найди `ONE_C_API_KEY`. Вставь его значение в поле **КлючОбмена** обработки 1С. Не отправляй его в чат и не публикуй на GitHub.
3. В 1С нажми **Отправить каталог в TEXHORU**. Каталог отправляется порциями по 50 товаров. Каждый пакет применяется одной транзакцией; если связь оборвалась между пакетами, повтори экспорт — GUID, артикулы и slugs предотвращают создание дубликатов.
4. Проверь цены в админке, подтверди связи.
5. В 1С нажми **Получить мониторинг из TEXHORU**. Она заберёт до 100 сообщений, сохранит их в регистр и передаст подтверждения. Если очередь большая, нажми снова.
6. При обрыве связи после сохранения в 1С можно повторить получение: ID сообщений не меняются до подтверждения.

Веб-сервер, IIS, Apache, COM и публикация базы 1С для этой схемы не нужны: инициатор запросов — сама 1С. Если учебная поставка запрещает HTTP-функции, используй файловый путь из раздела 6.

## 8. Массовый мониторинг и расписание

- После одного успешного товара запусти **1 страницу** раздела. Карточки конкурента сохраняются отдельно от каталога магазина; новые товары магазина не создаются.
- Затем выбирай **5 / 20 / 100 страниц**. Парсер следует реальной ссылке следующей страницы; после достижения лимита в задаче показывается ссылка для следующего запуска.
- Интервал запросов ограничивает локальный рабочий цикл; одна карточка обрабатывается за раз. Точное время зависит от загрузки Chromium и сайта. Один локальный backend обслуживает одну очередь.
- Задачи хранят курсор в SQLite. После перезапуска незавершённая задача восстановится после истечения аренды (до 3 минут). Между записью результата карточки и продвижением курсора есть небольшое окно: при аварии эта карточка может провериться повторно, что создаёт второе реальное наблюдение, но не теряет данные.
- Ошибки доступа/перегрузки останавливают задачу с сохранённой ссылкой. Для продолжения после устранения причины нажми **Продолжить**. Остановка допускает завершение уже начатой карточки.
- **Проверить все цены** проверяет все уже сохранённые ссылки. Расписание **2 часа / 6 часов / сутки** запускает такие же проверки, пока TEXHORU работает. Оно не открывает заново весь маркетплейс и не изменяет цены магазина.
- Первая версия извлекает характеристики iPhone и части моделей Samsung из названий, а также структурированных полей. Для прочих категорий используй GTIN/MPN и ручное подтверждение; универсальное распознавание любых моделей пока не заявляется.
- При единственном совпадении валидного GTIN и отсутствии противоречий связь подтверждается автоматически. Для MPN дополнительно нужны все обязательные характеристики; иначе требуется ручное подтверждение. Остальные случаи требуют подтверждения человека.
- Баллы в списке кандидатов — способ сортировки, не статистическая вероятность совпадения.
- Изменение имени/характеристик товара 1С или карточки конкурента блокирует действующую связь до повторного подтверждения. Изменение цены связь не ломает.
- Продавец и регион сохраняются по доступным полям. Если их нет, показано «не определён»; они не выдумываются. На проверенной карточке регион — Махачкала. Выбор произвольного региона и фильтра продавца пока не реализован: перед рабочим использованием согласуй нужный регион.
- В админке показаны все карточки в счётчиках, первые 100 подходящих карточек в списке, последние 100 сообщений и 20 задач. Для остальных карточек уточни поиск.

## 9. Рекомендации и перенос в базу работодателя

Рекомендация «цена конкурента − 500 ₽» показывается только при подтверждённой связи, известном наличии, успешной проверке не старше 24 часов, известной себестоимости, результате не ниже себестоимости и отклонении от нашей цены не более 10%. Это ориентир, а не механизм автоматического ценообразования.

В рабочей конфигурации нужно отдельно определить:

1. Где хранятся номенклатура и варианты (характеристики), штрихкоды и MPN.
2. Какой вид цены и склад брать для экспорта; как получать себестоимость.
3. Какие продавец и регион 05.ru нужны для сравнения, обычная ли это цена или цена по акции.
4. Где хранить результаты: независимый регистр мониторинга и журнал принятия решений.
5. Как менеджер согласовывает изменения и какой документ 1С устанавливает новую собственную цену.
6. HTTPS-адрес серверного TEXHORU и отдельный интеграционный ключ с нужными правами.

Модули из этой папки нельзя вставлять в конфигурацию работодателя без адаптации. Учебная платформа используется для разработки/тестов; рабочая эксплуатация — на коммерческой версии. После адаптации товар должен идентифицироваться парой GUID номенклатуры и GUID характеристики, если это отдельные объекты.

Для SQLite обновление проверено на временной тестовой базе. PostgreSQL-схема обновлена вместе с локальной, но миграция реальной PostgreSQL-базы и работа нескольких backend-процессов не проверялись. Для production понадобится отдельный план миграции, очередь с одним владельцем и адаптер 1С.

## Справка по протоколу

Все пути ниже начинаются с `/api`. Для прямого обмена требуется заголовок `x-1c-key`.

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/integrations/1c/catalog` | Импорт каталога 1С, атомарный для одного пакета |
| GET | `/integrations/1c/price-monitor/pending` | Неподтверждённые результаты, до 100 |
| POST | `/integrations/1c/price-monitor/receipts` | Пакет подтверждений `{items:[{id,error?}]}` |
| POST | `/integrations/1c/price-monitor/:id/ack` | Подтверждение одного сообщения |

Наблюдение содержит `schemaVersion`, `historyId`, `oneCId`, `competitor`, `url`, `price`, `oldPrice`, `inStock` (true/false/null), `checkedAt` (UTC ISO), `seller`, `region`, `attributes`, `recommendedPrice` (число/null), `recommendationReasons`. `id` сообщения используется для идемпотентной записи. Файловый экспорт содержит `{schemaVersion:1,items:[...]}`. Каталог содержит `{categories:[...],products:[...]}`. Квитанции содержат только `{items:[...]}`.
