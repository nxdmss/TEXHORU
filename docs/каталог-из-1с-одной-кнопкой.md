# Каталог из 1С одной кнопкой

Для основной базы с закупочной и обновлением «Розничной» используйте [отдельный основной профиль](основная-база-1с.md) и `UT103-MainBaseSync-FormModule.bsl`. Старый модуль ниже предназначен для прежней выгрузки без основного профиля.

**Кнопка в 1С:** «Обновить товары на сайте». Она читает каталог, цены и остатки, показывает прогресс, сохраняет точку продолжения и отправляет данные частями. Запись в 1С не выполняется. Тестовые ограничения обратного обмена ценами остаются отдельными.

Исходный модуль находится в `onec/monitoring/UT103-CatalogSync-FormModule.bsl`. Это **исходник для внешней обработки УТ 10.3 на платформе 8.3, не готовый файл `.epf`**. В этой среде нет 1С: сборка в конфигураторе и испытание на копии конкретной базы ещё обязательны. Для УТ 11, Розницы, ERP или другой конфигурации запросы необходимо адаптировать.

## Как организована нагрузка

| Участок | Ограничение |
| --- | --- |
| Выборка в 1С | 50 позиций за шаг по курсору ссылки; без массива всей номенклатуры |
| Получение цен и остатков | По одному групповому запросу для текущих 50, без запроса на каждый товар |
| Отправка | Один HTTPS-запрос за раз; между шагами неблокирующая пауза 1 секунда |
| Сервер | Максимум 100 товаров, 100 категорий и 512 КБ на пакет нового протокола |
| Повтор после ошибки | 2, 4, 8, 16, 32 секунды; затем остановка с сохранением прогресса |
| Серверное состояние | Один сеанс, номер следующего пакета и результат последнего; товары повторно не буферизуются в памяти |
| Поиск дублей | Индекс варианта и не более 100 точечных поисков; полный каталог на каждый пакет не читается |
| Старые записи | Первичная индексация по 200 строк; затем обрабатываются только строки с пустым индексом |
| Каталог покупателя | Сначала до 100 товаров, следующие страницы по 24; поиск/сортировка большого каталога на сервере |
| Журналы | Существующая ежедневная очистка успешных технических записей; завершённые сеансы старше 30 дней удаляются порциями |

Фотографии, двоичные вложения, документы, движения регистров и вся информационная база не пересылаются. Импорт сохраняет добавленные на сайте фото, описание и характеристики. Нулевые остатки тоже передаются: распроданная позиция не остаётся в наличии на сайте. Пометка удаления архивирует позицию сайта.

Количество товаров в базе и общий объём фотографий всё равно занимают постоянный диск. Эти ограничения сдерживают разовую нагрузку, но не заменяют контроль свободного места и плановое увеличение диска при росте ассортимента. Служебный старый `/api/products` сохранён для совместимости; витрина использует новый постраничный API. Служебный список товаров админки пока загружается целиком — для очень большого каталога его также следует разбить на серверные страницы.

## Первая установка в 1С

Разработчик 1С создаёт внешнюю обработку с **обычной формой** и вставляет модуль. Реквизиты формы:

| Имя | Тип / значение |
| --- | --- |
| `ХостСайта` | Строка, настоящий домен без `https://`, слэша и порта |
| `КлючAPI` | Строка, действующий отдельный `ONE_C_API_KEY` сервера |
| `ИдентификаторБазы` | Строка, постоянный ID этой базы, например `shop-ut103` |
| `ПапкаОбмена` | Строка, отдельная постоянная папка, например `C:\TEXHORU-Catalog` |
| `ТипЦен` | `СправочникСсылка.ТипыЦенНоменклатуры`, розничный тип цен **в рублях и базовых единицах** |
| `ГруппаВыгрузки` | `СправочникСсылка.Номенклатура`, необязательно; пустая — весь каталог, группа — её иерархия |
| `ПолнаяВыгрузка` | Булево, по умолчанию Ложь |

Кнопка «Обновить товары на сайте»: действие `ТЕХОРУОбновитьТоварыНажатие`. Дополнительная кнопка «Приостановить»: `ТЕХОРУОстановитьВыгрузкуНажатие`. Перед закрытием формы приостанавливайте обмен, чтобы не оставлять обработчик ожидания работающим.

Папка должна быть доступна на запись, не находиться в `%TEMP%` и сохраняться между запусками. **Один процесс 1С на эту папку и одну базу.** Не запускайте две обработки на разных компьютерах одновременно. Сервер допускает только один активный сеанс каталога; второй получит конфликт.

Для каждой пары **база + сайт + группа + тип цен** нужна отдельная папка обмена. Не переносите локальный кэш между серверами: новый магазин требует полной загрузки. Ключ API не сохраняется в файлах прогресса. Не кладите папку обмена в репозиторий или общедоступное облако.

Первый запуск сам выбирает полную передачу. Последующие сканируют локальную номенклатуру страницами и сравнивают маленькие файлы подтверждённых данных по GUID: на сервер уходят только изменения. Это экономит сеть и запись на сайте; **это не реализация регистра регистрации изменений 1С**. При сотнях тысяч позиций следующий этап — план обмена/регистрация изменений в расширении: тогда не нужен даже локальный полный проход.

## Что проверить на вашей копии УТ 10.3

1. Реквизиты и имена регистров совпадают с модулем, обычная форма поддерживает JSON и обработчик ожидания.
2. Розничный тип цен задан в рублях и правильных единицах. Автоконвертация валют и единиц не реализована. Дробные цены/остатки останавливают выгрузку: эта версия рассчитана на целые рубли и штучный товар. При нескольких различных базовых ценах обработка останавливается.
3. Выборки остатков и цен на вашей конфигурации соответствуют правилам продажи. Сейчас берутся базовые позиции с пустой характеристикой и суммарные остатки складов. Характеристики не объединяются в один SKU. Если товары продаются по характеристикам, их надо отдельно реализовать с отдельным стабильным ID, ценой и остатком, прежде чем подключать эту обработку к такому ассортименту.
4. Пробная небольшая группа: цены, остатки, фото сайта, категории и отсутствие дублей правильные.
5. Обрыв соединения после записи пакета: следующий запуск продолжает его без дублей.
6. Повтор без изменений: проверяются позиции, на сервер отправлено 0. Изменение цены/остатка/имени/группы отправляет нужные позиции. Нулевой остаток и пометка удаления отражаются на сайте.
7. Физически удалённый из 1С объект отсутствует в проходе. Автоматического удаления таких объектов на сайте нет. Сначала передавайте пометку удаления либо добавляйте tombstone через регистрацию изменений.

Набор данных меняется во время выгрузки, поэтому это не общий транзакционный снимок всей 1С. Изменения в уже пройденных позициях попадут в следующий запуск.

## Если связь оборвалась

Не удаляйте файлы прогресса. Нажмите кнопку снова с прежними параметрами. Обработка сохраняет пакет до отправки и записывает подписи только после ответа. Сервер записывает товары и номер следующего пакета одной транзакцией; повтор последнего идентичного пакета возвращает тот же результат. Повтор с иным содержимым получает 409.

Сеанс без связи более 24 часов может быть заменён новым. При закрытом/истёкшем сеансе: остановите обработку; в управлении магазином → **Обмен с 1С** остановите старый сеанс при необходимости; переместите `state.bin` и `state.bak` в отдельную резервную папку и запустите новую **полную** выгрузку. Уже принятые товары сохраняются. При повреждённом `state.bin` можно восстановить его из `state.bak`, сохранив копии обоих файлов; если сервер сообщает конфликт, начните новый полный сеанс по указанной процедуре.

## Серверный протокол

Все операции агента требуют `x-1c-key` и HTTPS:

- `POST /api/integrations/1c/catalog-sync/start` — `{sessionId: UUID, clientId, mode: FULL|DELTA}`. Повторный start возвращает состояние того же сеанса.
- `POST /api/integrations/1c/catalog-sync/:id/batch` — `{batch: 0, categories: [...], products: [...]}`. Ответ: `nextBatch`, `pauseMs`, принятые и пропущенные позиции.
- `POST /api/integrations/1c/catalog-sync/:id/finish` — закрытие сеанса, повтор безопасен.
- `GET /api/admin/integrations/1c/catalog-sync` — состояние в админке; доступ только сотруднику.
- `POST /api/admin/integrations/1c/catalog-sync/:id/cancel` — остановка сеанса; принятые товары не откатываются.

Старый `POST /api/integrations/1c/catalog` сохранён, но принимает не более 100 товаров и 500 категорий за запрос. Поставляемые старые выгрузки уже отправляют по 50. Новый протокол предпочтителен для долговременного прогресса и экономной повторной передачи.
