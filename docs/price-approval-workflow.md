# TEXHORU — ручное обновление цен из парсера

## Работа менеджера

1. Парсер 05.ru собирает свежие цены и формирует предложения. Сам парсер **не меняет цены**.
2. Откройте **Админка → Обновление цен**.
3. Нажмите **«Проверить цены»**, если нужны свежие данные.
4. Отметьте отдельные товары или нажмите **«Выбрать все»**.
5. Нажмите **«Обновить выбранные в 1С»**. В очередь попадают только отмеченные предложения.
6. Агент 1С получает очередь, сверяет текущую розничную цену, проводит документ и отправляет квитанцию.
7. Только после успешной квитанции TEXHORU меняет цену на сайте. До этого на витрине остаётся прежняя цена.

## Что видно в интерфейсе

- **Найдено** — доступные предложения парсера.
- **Выбрано** — отмеченные строки.
- **Ожидают 1С** — переданные, но ещё не подтверждённые изменения.
- **Ошибки** — конфликты и неудачные передачи.

Обновлять можно только товары, заранее включённые в разрешённую область обмена с 1С. Категории и товары вне этой области не попадут в очередь. Если агент 1С не запущен, выбранные изменения останутся в статусе ожидания.

## Защитные ограничения

- Автоматическая проверка парсера не меняет цены сайта или 1С.
- Запись в 1С начинается только после нажатия менеджером кнопки для выбранных строк.
- Применяются только подтверждённые привязки к 05.ru, свежие цены (не старше 24 часов) и товары из разрешённой области 1С.
- Для предложений требуется известная закупочная цена и минимальная маржа (по умолчанию 5%).
- Изменение более 10% не предлагается автоматически.
- Если по товару уже есть ожидающая запись 1С, второе задание не создаётся.
- 1С проверяет ожидаемую старую цену и GUID товара. При несовпадении документ не проводится.
- Сайт публикует новую цену только после успешной квитанции 1С.
- Каждая операция фиксируется в аудите.

## Запуск агента 1С

1С закрыта от входящих подключений. Сайт не может сам открыть базу и записать цену. Агент на Windows должен опросить очередь:
- вручную кнопкой/вызовом `RunPending`, либо
- через отдельно установленное регламентное задание.

Текущая тестовая обработка принимает до 30 разрешённых GUID и до 10 изменений за один цикл. Для проверки сначала используйте только TEST-базу. Рабочую базу не подключайте, пока отдельно не проверены резервная копия, область GUID и проведение документа.
