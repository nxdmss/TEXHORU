# Этап: изменение цены в TEXHORU → 1С

В старой версии админка напрямую меняла `Product.price`, не создавая запись в `OneCPriceChange`. Поэтому сайт и 1С могли расходиться.

Теперь при редактировании цены у товара, **заранее подключённого к обмену на стороне 1С**, `ProductsService.update` в одной транзакции:
1. Проверяет существующий товар 1С и неизменный GUID.
2. Проверяет включение в согласованную группу обмена.
3. Проверяет, что по товару нет предыдущего `PENDING`.
4. Создаёт `OneCPriceChange` с предыдущей и новой ценой, фиксированным ID и источником `null` (изменение вручную, без 05.ru).
5. Обновляет цену сайта с защитой от гонки.
6. Пишет аудит.

Агент 1С через `GET /api/integrations/1c/price-sync/pending` получает задание, сравнивает старую цену в выбранном розничном типе цены, создаёт документ и отвечает квитанцией `POST .../receipts`. Статусы `PENDING`, `DELIVERED`, `CONFLICT` и ошибки показываются в админке → 1С.

Редактирование цены импортированного товара **вне области обмена блокируется**, иначе сайт показал бы новую цену, а 1С перезаписала её старой при следующем импорте.

**Ограничения:** пилотная обработка для УТ 10.3 пока запускается вручную и исходник BSL не проверен в реальной системе пользователя. Максимум 30 выбранных GUID в области; до 10 сообщений за один сеанс. Первое испытание только в тестовой базе на одном товаре. После этого можно добавить регламентный запуск 1С и расширить область.
