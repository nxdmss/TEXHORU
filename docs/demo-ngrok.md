# Демонстрация TEXHORU через ngrok

Схема: сайт и ngrok на компьютере демонстратора, агент на компьютере с тестовой 1С. После входа в Windows начальнику достаточно открыть сайт. Агент работает при входе той Windows-учётной записи, которая его установила. Один только экран входа Windows не запускает обмен.

## Один раз перед показом

На компьютере демонстратора нужны Node.js 22+, установленный и настроенный ngrok (`ngrok version`), постоянный HTTPS-домен из своего аккаунта ngrok. Убедись, что ручной запуск ngrok с этим доменом работает. Авторизация ngrok остаётся в его локальной конфигурации; ключи в чат не отправляй.

Сохрани существующий `server/.env.local`, базу и uploads. Для обмена с TEST в этом файле должны быть явно заданы `ONE_C_BASE_KIND=TEST` и `ONE_C_TEST_PRICE_SYNC_ENABLED=true`, а ключ 1С должен совпадать с настроенным агентом. Запуск демонстрации не меняет эти флаги и не сбрасывает данные.

Останови предыдущий TEXHORU через `TEXHORU-STOP-WINDOWS.cmd`, а вручную запущенные сервер и ngrok — в их окнах. Дважды нажми **TEXHORU-DEMO-WINDOWS.cmd**. При первом запуске введи закреплённый HTTPS-домен ngrok. Он сохранится в `.texhoru/demo.json`; для смены адреса отредактируй поле `domain` при остановленной демонстрации. У агента `ApiHost` должен совпадать с этим доменом.

Первый запуск готовит зависимости, SQLite и сборку в кэше; последующие используют готовые файлы. В демонстрации API и собранный интерфейс работают на одном порту 3000. Vite, TypeScript watch и слежение за исходниками постоянно не запускаются. Действующий Edge на Windows используется парсером; собственный профиль пользователя не открывается.

Готовность объявляется после проверки БД через `/api/health`, совпадения проекта и загрузки страницы через ngrok. Сообщения об ошибках и журналы — в `.texhoru/demo-*.log`. Оставь окно запуска открытым. Остановка — **TEXHORU-STOP-WINDOWS.cmd**; она завершает только процессы этого запуска. Для локальной проверки без ngrok: `npm run demo -- --local`.

## Обновление агента на компьютере с TEST

1. В Конфигураторе открой свою внешнюю обработку EPF. Замени **весь модуль обычной основной формы** текстом [UT103-PilotRetailPrices-FormModule.bsl](../onec/monitoring/UT103-PilotRetailPrices-FormModule.bsl). Проверь синтаксис и сохрани отдельный новый EPF. Конфигурацию документа 1С менять не нужно.
2. Скопируй папку `onec/agent` с обновлением на компьютер начальника. Закрой старые окна ручного обмена. Под той же учётной записью Windows, что ставила агент, дважды нажми **UPDATE-WINDOWS.cmd** и укажи путь к новому EPF в запросе `EpfPath`. Либо запусти в PowerShell из этой папки:

```powershell
.\Update-TEXHORUAgent.ps1 -EpfPath 'C:\путь\к\новому\TEXHORU-Agent.epf'
```

Обновление сохраняет настройки, ключ и вход в 1С. Перед заменой делает резервную копию скриптов и EPF в папке агента. Активный обмен не прерывает: при занятом агенте нужно дождаться завершения. При успешном обновлении включает задачу **TEXHORU 1C Test Agent**, добавляет запуск при входе в Windows и проверку каждые две минуты. Если обновление прервалось, расписание остаётся отключённым. Старый EPF не совместим с новым протоколом результата: обновить нужно **оба**, EPF и скрипты.

Для нового компьютера используется `Install-TEXHORUAgent.ps1`, как описано в [инструкции агента](../onec/agent/README.md).

## Как показывать

1. Запусти демонстрацию. Начальник входит в Windows, сайт показывает последнюю связь с агентом в **Обмен с 1С**.
2. Существующей обработкой выгрузи выбранные товары из TEST на сайт. Импорт не запускает изменение цен в 1С.
3. В **Цены** запусти поиск/проверку конкурента. Дождись реального результата; сеть, защита 05.ru и количество товаров влияют на время. Сам показ не включает автоматическую отправку цен.
4. Выбери предложения и нажми **Отправить выбранные в 1С**. За один сеанс агент обрабатывает максимум три пакета по десять товаров. Область обмена остаётся ограниченной 30 разрешёнными товарами.
5. Дождись статуса **Выполнено**, затем покажи цены в TEST и на сайте. Предложения парсера публикуются на сайте только после подтверждения 1С. Счётчики на экране охватывают всю очередь; список показывает последние 30 операций.

Пустая очередь не запускает 1С. Ошибка в пакете останавливает следующие пакеты текущего сеанса; повтор откладывается на 2, 4, 8, затем 10 минут. Подтверждённые операции повторно не записываются. При пропавшем сайте очередь сохраняется на сервере. После восстановления соединения агент повторит запрос по расписанию. Причины ошибок отдельных товаров видны на сайте, а не скрыты за словом «обработано».

Статус «на связи» означает недавний отчёт агента (не старше пяти минут), а не гарантию записи цены. Запись подтверждает отдельная квитанция **Выполнено**. Если агент ожидает отложенного повтора, связь может стать несвежей — время последней связи показано рядом.

## Проверка после установки

Проверь пустую очередь (1С не открывается), один товар, группу до 30 товаров, временное выключение сайта и повтор после включения. На каждом этапе сравни цены в TEST и на сайте. Проверь также выход/вход в Windows и перезапуск демонстрации. Автотесты в Linux проверяют API, протокол и запуск подставного процесса; реальное проведение, EPF и планировщик Windows нужно проверить на вашем компьютере.
