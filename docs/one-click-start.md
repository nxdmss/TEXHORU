# Запуск одной кнопкой

Пользователь открывает TEXHORU.exe. Native Go launcher находит Node.js 22+ либо загружает официальную переносимую Windows-версию с проверкой SHA-256, затем запускает scripts/auto-start.mjs.

Подготовка вычисляет отпечаток исходников и зависимостей. Приложение копируется в новый каталог `%LOCALAPPDATA%/TEXHORU/cache/<project-id>/app-*`; туда устанавливаются зависимости. Старый node_modules пользователя не очищается и не используется. Это устраняет удаление заблокированной папки react-native/React, на котором упал прежний npm ci в OneDrive.

Prisma client и backend собираются в кеше. DATABASE_URL указывает на оригинальную SQLite-базу, TEXHORU_UPLOADS_DIR — на оригинальные фотографии. Перед новым изменением схемы копируются база с журналами, env и фотографии. Seed выполняется только для новой базы, с сохранением признака незавершённого первого создания. Существующая учётная запись не пересоздаётся.

Повторный запуск использует подготовленный кеш. При изменении кода собственная работающая копия останавливается через локальный управляющий канал с непредсказуемым токеном. Посторонние процессы не завершаются. Старую копию без этого канала потребуется закрыть вручную один раз.

Backend получает завершение по IPC, закрывает NestJS/Prisma и только затем заканчивает работу. TEXHORU STOP.exe использует тот же защищённый управляющий канал. Неавторизованная команда остановки отклоняется. Для ручного запуска остаётся совместимость с npm run dev и cmd-кнопками.

Проверено: первый запуск из папки с пробелами и OneDrive в пути; старая папка зависимостей остаётся нетронутой; повторная подготовка использует кеш; сайт отвечает; фотографии читаются из оригинальной папки; существующие товары, цены, остатки, резервы и пароль администратора сохраняются; повторное открытие не создаёт второй экземпляр; остановка завершает процессы приложения. Эти исполняемые проверки проведены в Linux. Windows EXE проверен как PE32+ x64 и успешно собран; выполнение его на Windows здесь недоступно.

Сборка EXE из исходников (Go 1.23.2+): `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags="-s -w"` из scripts/launcher. Для кнопки остановки используется флаг `-X main.mode=stop`. Бинарники должны лежать рядом с package.json в корне проекта.
