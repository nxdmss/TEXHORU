# TEXHORU на Яндекс Cloud — по шагам

Подготовлен запуск на одной Ubuntu 24.04 LTS: приложение, постоянная SQLite-база, фотографии и Caddy с HTTPS. Ngrok, отдельный PostgreSQL, Object Storage и балансировщик на этом этапе не нужны. Это один сервер с TEST-обменом, без отказоустойчивого кластера. Ресурсы в Яндексе ещё не созданы и не оплачены.

Автоматические бэкапы и снимки не настроены по просьбе владельца. При утрате единственного диска восстановить данные будет неоткуда. Исходный Windows-сайт и база 1С установщиком не изменяются.

## 1. Аккаунт и расходы

Открой [консоль Яндекс Cloud](https://console.yandex.cloud/), создай платёжный аккаунт, облако и каталог TEXHORU. Подключи бюджет и уведомления о расходах. Бюджет предупреждает, но не останавливает списания автоматически. До создания проверь стоимость VM, диска, публичного IP и исходящего трафика. Остановка VM не прекращает оплату сохраняемого диска и зарезервированного IP.

Не отправляй в чат платёжные данные, пароли, приватный SSH-ключ или ключ интеграции. По конкретным экранам консоли можно пройти вместе с помощником.

## 2. SSH-ключ на Windows

На своём компьютере в PowerShell:

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.ssh" | Out-Null
$key = "$env:USERPROFILE\.ssh\texhoru_yandex"
if (-not (Test-Path $key)) { ssh-keygen -t ed25519 -f $key -C 'texhoru-yandex' }
Get-Content "$key.pub"
```

В Яндекс копируется строка из **.pub**, а файл без `.pub` остаётся у тебя. Если задашь парольную фразу, SSH будет её спрашивать.

## 3. Создать VM

Compute Cloud → **Создать виртуальную машину**:

| Настройка | Первый запуск |
| --- | --- |
| Образ | Ubuntu 24.04 LTS, x86_64 |
| CPU | 2 vCPU, гарантированная доля 100% |
| RAM | 4 ГБ: приложению до 2,5 ГБ, остальное ОС и прокси |
| Диск | SSD, 30 ГБ — контейнер содержит браузер парсера |
| Прерываемая | Нет |
| IP | Публичный IPv4, зарезервировать статический |
| Доступ | SSH-ключ, логин `ubuntu` |
| Сервисный аккаунт | Не нужен для этого варианта |

В группе безопасности разреши **TCP 22 со своего IP**, **TCP 80/443 из интернета**, исходящие DNS и HTTPS. API 3000 и базу наружу не открывай. Не подключай Cloud Backup или политики снимков диска.

Сохрани IP. Подключение из PowerShell, заменив `PUBLIC_IP`:

```powershell
ssh -i "$env:USERPROFILE\.ssh\texhoru_yandex" ubuntu@PUBLIC_IP
```

## 4. Домен

Нужен домен, которым ты управляешь, например `shop.example.ru`. Домен покупается у регистратора: создание зоны Cloud DNS само по себе его не покупает. Можно оставить DNS у регистратора.

Создай **A-запись** выбранного имени на статический IP VM. Не оставляй AAAA-запись на другой сервер. Дождись обновления DNS. Один и тот же домен дальше используется сайтом и агентом.

## 5. Установить на VM

Следующие команды выполняются **в SSH на сервере**. Замени домен и email:

```bash
curl --fail --show-error --location --output /tmp/texhoru-install.sh https://raw.githubusercontent.com/nxdmss/TEXHORU/main/deploy/cloud/install.sh
sudo bash /tmp/texhoru-install.sh --domain shop.example.ru --email director@example.ru
```

Установщик ставит Docker из официального репозитория, забирает `main`, собирает приложение и запускает его. Первичная сборка занимает несколько минут. Пароль, JWT и ключ 1С генерируются на VM. Повторный запуск не сбрасывает их. Открывай сайт только по HTTPS.

```bash
sudo texhoru status
sudo texhoru credentials
```

Вторая команда показывает локальные секреты **тебе**, не присылай вывод в чат. Сохрани пароль в менеджере паролей. Открой `https://shop.example.ru/admin`, в том числе с iPhone.

Если сайт не открывается, проверь A-запись, 80/443 и `sudo texhoru logs`. Для публичного сертификата домен уже должен указывать на VM. Не отключай проверку TLS и не переключай сервер в development.

Новая база пустая, кроме администратора. Есть два пути: **чистый старт с новой выгрузкой из TEST** либо **перенос существующих данных до начала работы с облачным каталогом**.

## 6. Необязательный однократный перенос данных

### Только товары и привязки — сохранить облачный пароль

Если новый облачный кабинет уже настроен, используй этот вариант. Переносятся разделы, товары, GUID 1С, разрешения TEST, фото, карточки/привязки 05.ru, две последние цены и настройки проверки. Пользователи, пароли, заказы, старые задания и очереди не включаются. Резервы старых заказов обнуляются только в переносимой копии товаров; исходная база не меняется.

На Windows-компьютере старого сайта:

```powershell
cd "C:\Users\umarc\OneDrive\Desktop\TEXHORU-NEW"
.\TEXHORU-STOP-WINDOWS.cmd
git pull --ff-only origin main
node --disable-warning=ExperimentalWarning scripts/export-cloud-catalog.mjs
scp -i "$env:USERPROFILE\.ssh\texhoru_yandex" -r .\.texhoru\catalog-transfer ubuntu@PUBLIC_IP:~/
```

Экспорт работает без установленных npm-зависимостей, на Node.js 22.13 или новее. Сначала останови старый сервер. Наличие старых незавершённых очередей не мешает этому варианту: они остаются в старой базе и не запускаются на новом сайте. После экспорта старый сайт оставь выключенным.

На VM:

```bash
sudo git -C /opt/texhoru pull --ff-only origin main
sudo texhoru import-catalog /home/ubuntu/catalog-transfer
```

Образ пересобирать не нужно. Во время импорта API ненадолго останавливается и затем запускается. Импорт проверяет контрольную сумму, схему и связи; не перезаписывает используемый каталог. Облачные пользователи, новый пароль, текущий ключ 1С и статус агента сохраняются. После переноса обнови страницу и нажми **Проверить цены разрешённых**: старая цена конкурента может требовать свежей проверки. Перед отправкой проверь актуальность розничной цены/остатка в TEST.

### Полная база — заменяет облачные аккаунты

Этот вариант нужен только если требуется перенести также старые учётные записи и историю заказов. В отличие от каталога, он заменяет облачный логин и пароль старыми.

Экспорт сохраняет базу, пользователей, привязки и фотографии, но не `.env` и не ключ интеграции. Это однократная передача, не расписание резервного копирования. Сначала заверши очередь 1С и останови проверки на старом сайте.

На Windows-компьютере сайта (Node.js 22.16 или новее):

```powershell
cd "C:\Users\umarc\OneDrive\Desktop\TEXHORU-NEW"
.\TEXHORU-STOP-WINDOWS.cmd
git pull --ff-only origin main
node scripts/export-cloud-data.mjs
scp -i "$env:USERPROFILE\.ssh\texhoru_yandex" -r .\.texhoru\cloud-transfer ubuntu@PUBLIC_IP:~/
```

Экспорт создаёт согласованную standalone SQLite-копию через SQLite API, включая данные WAL, и фотографии в `.texhoru/cloud-transfer`. Откажется работать при активном сервере, незавершённой очереди/проверке либо существующей папке переноса. Исходная база не очищается.

На VM:

```bash
sudo texhoru import-data /home/ubuntu/cloud-transfer
sudo texhoru status
```

Импорт проверяет контрольную сумму, целостность SQLite, администратора и отсутствие активных передач. Откажется перезаписывать используемый облачный каталог. После переноса входи **старым логином и паролем сайта**, а ключ интеграции остаётся новым облачным. Не запускай одновременно старый сайт с той же очередью. Папки переноса можно удалить вручную после проверки; фоновых копий нет.

## 7. Переключить TEST-агент

На компьютере с агентом, под тем же Windows-пользователем, который его устанавливал. EPF не пересобирается: сохраняются база TEST, путь обработки и расписание.

В PowerShell, заменив домен:

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$script = Join-Path $env:TEMP 'Set-TEXHORUCloudEndpoint.ps1'
Invoke-WebRequest -UseBasicParsing -Uri 'https://raw.githubusercontent.com/nxdmss/TEXHORU/main/onec/agent/Set-TEXHORUCloudEndpoint.ps1' -OutFile $script
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $script -ApiHost 'shop.example.ru' -RunNow
```

В скрытый запрос введи новый `ONE_C_API_KEY` с VM. Скрипт проверяет сайт и ключ **до** изменения настроек, сохраняет ключ в защите Windows и отправляет heartbeat. Если агент занят, дождись конца цикла и повтори. Отключённую задачу скрипт не включает сам. Если требуется:

```powershell
Enable-ScheduledTask -TaskName 'TEXHORU 1C Test Agent'
Start-ScheduledTask -TaskName 'TEXHORU 1C Test Agent'
```

В отдельной ручной обработке выгрузки каталога тоже укажи новый домен и ключ: в некоторых версиях хост задан в модуле формы. Скрипт переключения агента не переписывает другие EPF. Проверь TEST → сайт, затем разреши один товар в подключении, получи свежую цену и проверь сайт → TEST → подтверждение. Только затем переходи к группе товаров. Порты на компьютере 1С открывать не нужно. Рабочая база этой установкой не подключается.

### Добавить новые товары после переезда

В админке открой **Главная → Новые товары** или **Цены → Подключить товары**:

1. **Товары из 1С.** В существующей обработке TEST выбери группу и повтори выгрузку на новый домен с облачным ключом. Существующие записи обновляются по идентификатору 1С. Нажми «Я выгрузил — обновить каталог».
2. **Допуск к обмену.** Найди товары по разделу или названию, отметь нужные и нажми «Разрешить обмен». Лимит TEST — 30; существующие допуски сохраняются. Это действие ещё не отправляет цены.
3. **Карточки 05.ru.** По умолчанию поиск идёт только среди разрешённых товаров. Открой нужный раздел и найди карточки; проверь спорные совпадения. Переключатель «Весь каталог» расширяет область только для отдельного поиска, не даёт разрешение на изменение цен.

Вернись к ценам: «Проверить цены разрешённых» получает свежие цены сохранённых карточек, «Обновить готовые» отправляет готовые изменения в 1С. Сайт публикует их после подтверждения 1С. Выбор отдельных товаров раскрывается по карточке группы. Подробные результаты свёрнуты под «Что обновилось».

Windows-агент цен не выгружает каталог автоматически. Для нового товара нужна отдельная выгрузка из той же TEST-базы; перенос SQLite для каждого пополнения не нужен.

## 8. Короткие команды

Сменить пароль администратора без остановки сайта:

```bash
sudo texhoru set-admin-password
```

Введи новый пароль дважды (ввод скрыт). Нужно от 16 символов, не более 72 байт UTF-8. Команда обновляет хеш в базе и локальные данные входа; пароль не попадает в историю команд. Если перенесённая база использует другой email: `sudo texhoru set-admin-password EMAIL`. Затем выйди из кабинета и войди новым паролем. Уже выданные сессии автоматически не отзываются.

На VM:

```bash
sudo texhoru status
sudo texhoru logs
sudo texhoru update
sudo texhoru restart
sudo texhoru stop
sudo texhoru start
```

`update` забирает `main`, собирает образ и заменяет контейнер, сохраняя базу/фотографии. Код: `/opt/texhoru`, секреты: `/etc/texhoru` (права 600), данные: `/var/lib/texhoru/{database,uploads,caddy}`. Caddy хранит рабочие сертификаты, это не бэкап базы.

Не используй `docker compose down -v`, `docker system prune --volumes`, `prisma migrate reset` и `--accept-data-loss`. Изменение схемы с потерей данных останавливает запуск, а не обнуляет базу.

## Ограничение нагрузки и роста данных

- Один API и worker; без Vite, режима разработки и постоянных пересборок. Перечитываются две страницы одновременно. Обновление готовых цен не сканирует каталог.
- Расписание в облаке проверяет только разрешённые активные товары. Неизменившиеся цены не создают дубликаты истории.
- SQLite WAL, короткие транзакции и ограничение журнала. Один экземпляр API; не подключай вторую VM к тому же файлу SQLite.
- Docker-журналы: до трёх файлов по 10 МБ на сервис; отдельный access log с запросами/заголовками не включён.
- Раз в сутки небольшими партиями очищаются служебные успехи, прочитанные уведомления, законченные задания и поисковый индекс старше 30 дней. Сохраняются два последних наблюдения цены и история незавершённых сообщений. При активной проверке очистка откладывается.
- Пользователи, товары, заказы, бизнес-аудит, отказы от предложений и подтверждения 1С автоматически не удаляются. Неразрешённые ошибки остаются видны.
- SQLite переиспользует освобождённые страницы: размер файла не обязан сразу уменьшаться. Ежедневного тяжёлого VACUUM нет.
- Автоматические резервные копии отключены по просьбе владельца. Это экономия места, а не отказоустойчивость.

## Границы проверки

Автотесты собирают production-образ и проверяют HTTPS через Caddy с локальным тестовым CA, защищённый вход, импорт/API-ключ 1С, сохранность каталога/фото после замены контейнера, неизменность пароля и запуск Chromium. Отдельно проверяются очистка и перенос.

Реальный Яндекс Cloud, публичный DNS/сертификат, доступность 05.ru с выбранного IP и проведение документов вашей 1С проверяются после создания VM и подключения домена. У магазина могут быть ограничения для облачных IP — успешный обход защиты установка не обещает.
