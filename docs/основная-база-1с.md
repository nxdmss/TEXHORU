# Основная УТ 10.3: каталог, закупочная и розничная цены

Исходный модуль обычной формы: `onec/monitoring/UT103-MainBaseSync-FormModule.bsl`. Это не скомпилированная EPF: в среде разработки нет платформы 1С. Перед работой обязательны синтаксический контроль и проверка проведения на копии конкретной УТ 10.3. Учёт по характеристикам, дробные цены/остатки, нестандартные регистры, валюты и упаковки требуют адаптации. Курс валют и пересчёт упаковок здесь не вычисляются; используются рубли и базовые единицы.

## Правило цены

`Розничная = max(актуальная цена подтверждённой карточки 05.ru − 100 ₽, Закупочная)`.

Например, 05.ru = 50 000, закупочная = 48 000 → розничная 49 900. При закупочной 49 950 → розничная 49 950. При неизвестной закупочной запись запрещена. Закупочная из 1С может быть 0, но должна быть явно известна; отрицательные и дробные значения не принимаются.

Новый тип цен не создаётся. Обработка проводит штатный документ `УстановкаЦенНоменклатуры` для выбранного существующего типа «Розничная». Прошлые документы не редактируются: сохраняется история, текущая цена берётся через срез последних. Прямая запись в регистры и прибавление к прежней цене не выполняются. Закупочный тип остаётся неизменным.

На сайте остаются проверки совпадения модели/варианта, наличия, свежести, области обмена и существенного отклонения (для основной базы — 10%). Рекомендация не является фактом обновления: сайт публикует цену только после квитанции проведённого документа 1С. Перед каждой записью обработка дважды проверяет текущую закупочную и ожидаемую старую розничную. После обрыва уже установленная целевая цена подтверждается без создания повторного документа.

## Форма обработки

Создай новую внешнюю обработку с обычной основной формой; сохрани прежнюю TEST-обработку отдельно. Вставь модуль целиком. Реквизиты формы:

| Имя | Тип | Значение |
| --- | --- | --- |
| ХостСайта | Строка 255 | Домен без схемы, порта, пути |
| КлючAPI | Строка 255 | Отдельный серверный ONE_C_API_KEY |
| ИдентификаторБазы | Строка 100 | Например `texhoru-main-ut103`, одинаково с сервером |
| ПапкаОбмена | Строка 500 | Новая отдельная папка для основной базы и группы |
| ТипЦен | СправочникСсылка.ТипыЦенНоменклатуры | Существующая «Розничная» |
| ЗакупочныйТипЦен | СправочникСсылка.ТипыЦенНоменклатуры | Существующая «Закупочная» |
| ГруппаВыгрузки | СправочникСсылка.Номенклатура | Небольшая группа для проверки, затем крупная с подгруппами |
| ПолнаяВыгрузка | Булево | Истина для первой загрузки после очистки |

Кнопки:

- «Выгрузить каталог»: `ТЕХОРУОбновитьТоварыНажатие`.
- «Применить розничные цены»: `ТЕХОРУПрименитьРозничныеЦеныНажатие`.
- «Приостановить»: `ТЕХОРУОстановитьВыгрузкуНажатие`.

Перед закрытием формы приостанови работающий обмен. Каталог и применение цен одновременно не запускаются. Каталог читается по 50 позиций; цена/остаток/закупочная выбираются пакетными запросами. Фото и документы в HTTP не передаются. Цены забираются по 10 заданий, максимум 30 за шаг обработчика ожидания, затем пауза 1 секунда. Отсутствующие в частичной группе товары не удаляются. Изменение закупочной входит в подпись DELTA; явный null очищает ранее сохранённую закупочную на сайте и блокирует автоматическое изменение.

## Профиль сервера

1. Останови прежнюю Windows-задачу `TEXHORU 1C Test Agent`. Не перенастраивай TEST-агент на рабочую базу: он остаётся отдельным TEST-инструментом.
2. Не смешивай очереди TEST и основной базы. Старые задания должны быть закрыты/отменены до переключения; старый локальный кэш не переносится. Очистка магазина выполняется только отдельной явно запущенной командой, установка этой версии ничего не удаляет.
3. Обнови сервер `sudo texhoru update`.
4. В `/etc/texhoru/app.env` задай:

```dotenv
ONE_C_BASE_KIND=PRODUCTION
ONE_C_TEST_PRICE_SYNC_ENABLED=false
ONE_C_PRODUCTION_BASE_ID=texhoru-main-ut103
ONE_C_PRODUCTION_PRICE_SYNC_ENABLED=false
```

5. Примени окружение пересозданием контейнера (обычный restart не перечитывает env):

```bash
cd /opt/texhoru
sudo docker compose --env-file /etc/texhoru/compose.env -f deploy/cloud/compose.yaml up -d --force-recreate --wait app
```

6. Проверь выгрузку небольшой группы: правильные GUID, иерархия, цены «Розничная» и «Закупочная», остатки. Запросы без `x-1c-base-kind: PRODUCTION` и точного `x-1c-base-id` отклоняются даже при правильном ключе. Новая обработка добавляет заголовки сама.
7. После проверки записи на копии измени `ONE_C_PRODUCTION_PRICE_SYNC_ENABLED=true` и повтори пересоздание. Прочие настройки (SMTP, домен, администратор) не меняй. TEST-флаг основную базу не включает. При первом включении основного профиля и при смене ID старые допуски сбрасываются, незавершённые задания отменяются. Затем повтори полную выгрузку основной базы (с галочкой «ПолнаяВыгрузка»): только она подключит актуальные товары. Последующие перезапуски с тем же профилем допуски сохраняют.
8. На сайте проверь/подтверди привязку к точной карточке 05.ru, проверь цену, выбери один товар и отправь изменение. В 1С нажми «Применить розничные цены». Проверь документ, текущую розничную, неизменную закупочную и квитанцию на сайте; затем расширяй группы.

Эта версия даёт ручной запуск кнопками обычной формы. Автоматический запуск на основной базе через старый TEST-планировщик не подключён. Скомпилировать и проверить EPF нужно на компьютере с 1С; одни Node/HTTP-тесты не подтверждают проведение документов вашей конфигурации.


## Выгрузка по команде из сайта

Для управления группами/очередью из админки появился отдельный read-only COM-агент. Установка: [Управление каталогом из сайта](управление-каталогом-из-сайта.md). Для него EPF не нужна. Применение розничных цен остаётся в описанной выше основной обработке.
