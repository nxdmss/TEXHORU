# TEXHORU: статусы первичного сопоставления 1С с 05.ru

## Зачем это нужно
После первого поиска результат сохраняется **отдельно для каждого товара 1С** и магазина. Ранее товар без привязанной карточки попадал в новый массовый поиск снова и снова.

| Статус | Значение | Следующий массовый поиск |
| --- | --- | --- |
| `CONFIRMED` | Точная карточка подтверждена | Не участвует при `onlyUnlinked=true`. Цена обновляется по сохранённой ссылке |
| `REVIEW` | Найдены похожие/неоднозначные варианты | Не участвует при `onlyUnlinked=true`, ждёт ручного решения |
| `NO_MATCH` | Поиск отработал корректно, подходящих карточек не нашли | **Всегда исключается**, пока пользователь не запустит повтор вручную |
| `RETRYABLE` | Сайт не ответил, выдача неполная или произошла ошибка чтения | Остаётся доступен для будущего массового поиска |
| `PENDING` | Ещё не проверен или пользователь запросил повтор | Доступен для первичной проверки |

`NO_MATCH` не означает, что товара никогда не будет у продавца. Это только выключение бессмысленного повторного поиска до ручного решения.

## Где смотреть
Админка → «Мониторинг цен» → вкладки «Подтверждены», «Под вопросом», «Нет совпадений» и «Не проверены / ошибки». В карточке товара с `NO_MATCH` находится кнопка «Повторить поиск вручную».

Эндпоинты (только администратор):
- `GET /api/admin/price-monitor/match-outcomes` — результаты проверки по 1С
- `POST /api/admin/price-monitor/match/:productId/retry` — повторный поиск одного товара

## Индексация и сопоставление
1. Для большой выборки смартфонов сначала заполняется локальный индекс `CompetitorCatalogEntry`.
2. Предварительный поиск не объявляет карточку несуществующей, если есть сбой чтения.
3. Строгая и расширенная выборка кандидатов работают совместно. Полная карточка подтверждается по характеристикам, а неоднозначные варианты остаются на проверку.
4. При следующем массовом запуске `NO_MATCH` не попадает в очередь, даже если `onlyUnlinked=false`.
5. Автопроверка каждые 6 часов использует **только подтверждённые ссылки**. Новый поиск в этом режиме не запускается; 1С не получает автоматических изменений цен без отдельного разрешения.

## Запуск на Windows
В каталоге проекта:

```cmd
git pull origin main
TEXHORU-WINDOWS.cmd
```

Штатный локальный запуск проверяет изменения `server/prisma/schema.local.prisma`, пересоздаёт Prisma Client и применяет `prisma db push` к рабочей локальной SQLite-базе с сохранением текущих товаров и истории.

Если сервер запускается вручную без штатного лаунчера, перед сборкой обновите схему:

```cmd
cd server
npm ci
npm run prisma:local:generate
npm run prisma:local:push
npm run build
```

Для PostgreSQL необходимо отдельно обновить схему в установленной БД; локальные команды SQLite не предназначены для него.

## Ограничения
- Автоматическое присвоение `NO_MATCH` требует хотя бы одной успешно считанной страницы с результатами, отсутствия необработанных кандидатов и ошибок парсинга.
- Реальная доступность 05.ru зависит от его публичной разметки и ограничений. Код не обходит 403/429.
- Старые неудачные поиски до обновления не станут `NO_MATCH` задним числом. Статус появится после нового первичного прогона.
