# История развития мониторинга и каталога

Прежние технические заметки объединены в один файл. Они сохранены для истории и диагностики; названия экранов, кнопок, ограничения и сценарии могут быть устаревшими. Актуальные инструкции — [документация](README.md).

## Первичное сопоставление 1С с каталогом 05.ru

### Новый порядок работы

1. TEXHORU получает товары 1С. В задания сопоставления попадают только активные позиции с `oneCId`, положительной ценой и доступным остатком (`stockQty > reservedQty`).
2. Если в выбранной выборке есть смартфоны и включена индексация, TEXHORU сначала постранично читает публичную категорию смартфонов 05.ru: `https://05.ru/cat/mc/396f7486/smartfony/`.
3. Ссылки и названия сохраняются в `CompetitorCatalogEntry`: нормализованные модель, память и цвет извлекаются из названия. Прогресс сохраняется после каждой страницы; после перезапуска задача продолжает с последней страницы.
4. Только после индекса запускается `MATCH_1C`. Система ищет кандидатов локально по модели и памяти, затем открывает до восьми наиболее подходящих карточек 05.ru и проверяет реальные характеристики.
5. Уникальный полный вариант может быть подтверждён автоматически. Несколько точных вариантов, неизвестные характеристики и расхождения остаются на ручную проверку.
6. Если в индексе нет подходящего кандидата, остаётся точечный публичный поиск как резервный путь. Это не повод автоматически объявлять товар отсутствующим.
7. После подтверждения мониторинг цен читает только сохранённые ссылки. Он не запускает новый поиск и не меняет цену TEXHORU или 1С без отдельного подтверждения.

### Что именно индексируется

Индекс первого этапа лёгкий: публичная ссылка, название, модель, память, цвет и дата последнего обнаружения. Это быстрый слой обнаружения, а не источник подтверждённой цены. Полные характеристики, цена и наличие читаются из самой карточки только для кандидатов, которые подходят под товар 1С. Так не приходится открывать тысячи заведомо нерелевантных карточек.

Успешный индекс смартфонов используется до семи дней. При отсутствии завершённого свежего индекса он строится заново. Пустая страница проверяется повторно; повторяющаяся пагинация или достижение защитного лимита не выдаются за полный каталог.

### Другие магазины

DNS и М.Видео используют отдельные адаптеры и поиск по своим публичным каталогам. Их индексы не смешиваются с 05.ru. Город для цен и наличия в DNS и М.Видео задаётся отдельно.

### Ограничения

- 05.ru может менять публичную разметку, пагинацию и доступность. При HTTP 403/429 обход ограничений не выполняется.
- Индекс названий и ссылок не гарантирует наличие товара или актуальность цены.
- Полная карточка повторно открывается перед сохранением совпадения и при каждом обновлении цены.
- Начинай с тестовой выборки и проверяй уникальность модели, памяти, цвета и SIM. Цена продажи не меняется автоматически.

## TEXHORU: статусы первичного сопоставления 1С с 05.ru

### Зачем это нужно
После первого поиска результат сохраняется **отдельно для каждого товара 1С** и магазина. Ранее товар без привязанной карточки попадал в новый массовый поиск снова и снова.

| Статус | Значение | Следующий массовый поиск |
| --- | --- | --- |
| `CONFIRMED` | Точная карточка подтверждена | Не участвует при `onlyUnlinked=true`. Цена обновляется по сохранённой ссылке |
| `REVIEW` | Найдены похожие/неоднозначные варианты | Не участвует при `onlyUnlinked=true`, ждёт ручного решения |
| `NO_MATCH` | Поиск отработал корректно, подходящих карточек не нашли | **Всегда исключается**, пока пользователь не запустит повтор вручную |
| `RETRYABLE` | Сайт не ответил, выдача неполная или произошла ошибка чтения | Остаётся доступен для будущего массового поиска |
| `PENDING` | Ещё не проверен или пользователь запросил повтор | Доступен для первичной проверки |

`NO_MATCH` не означает, что товара никогда не будет у продавца. Это только выключение бессмысленного повторного поиска до ручного решения.

### Где смотреть
Админка → «Мониторинг цен» → вкладки «Подтверждены», «Под вопросом», «Нет совпадений» и «Не проверены / ошибки». В карточке товара с `NO_MATCH` находится кнопка «Повторить поиск вручную».

Эндпоинты (только администратор):
- `GET /api/admin/price-monitor/match-outcomes` — результаты проверки по 1С
- `POST /api/admin/price-monitor/match/:productId/retry` — повторный поиск одного товара

### Индексация и сопоставление
1. Для большой выборки смартфонов сначала заполняется локальный индекс `CompetitorCatalogEntry`.
2. Предварительный поиск не объявляет карточку несуществующей, если есть сбой чтения.
3. Строгая и расширенная выборка кандидатов работают совместно. Полная карточка подтверждается по характеристикам, а неоднозначные варианты остаются на проверку.
4. При следующем массовом запуске `NO_MATCH` не попадает в очередь, даже если `onlyUnlinked=false`.
5. Автопроверка каждые 6 часов использует **только подтверждённые ссылки**. Новый поиск в этом режиме не запускается; 1С не получает автоматических изменений цен без отдельного разрешения.

### Запуск на Windows
В каталоге проекта:

```cmd
git pull origin main
TEXHORU-WINDOWS.cmd
```

Штатный локальный запуск проверяет изменения `server/prisma/schema.local.prisma`, пересоздаёт Prisma Client и применяет `prisma db push` к рабочей локальной SQLite-базе с сохранением текущих товаров и истории.

Если сервер запускается вручную без штатного лаунчера, перед сборкой обновите схему:

```cmd
cd server
npm ci
npm run prisma:local:generate
npm run prisma:local:push
npm run build
```

Для PostgreSQL необходимо отдельно обновить схему в установленной БД; локальные команды SQLite не предназначены для него.

### Ограничения
- Автоматическое присвоение `NO_MATCH` требует хотя бы одной успешно считанной страницы с результатами, отсутствия необработанных кандидатов и ошибок парсинга.
- Реальная доступность 05.ru зависит от его публичной разметки и ограничений. Код не обходит 403/429.
- Старые неудачные поиски до обновления не станут `NO_MATCH` задним числом. Статус появится после нового первичного прогона.

## TEXHORU · ускоренная первая привязка (November 2026)

This optimization applies to the **first** 1C → competitor discovery/matching run.
It does **not** relax the exact-variant check or change prices in 1C.

- **05.ru category index:** persist URL/title/model hints once, reuse by all 1C variants.
  A completed (<=7 days old) index suppresses an otherwise redundant 50-page
  in-memory category crawl inside EACH live search. Live store search still runs
  if the index did not produce a suitable match.
- **Read-once page cache:** during initial matching, verified 05.ru product-page
  observations are reused for three minutes (maximum 600 URLs). Concurrent
  requests for the same URL share the first read. Failed pages are not cached.
  **Scheduled six-hour monitor always uses parse(), which fetches live pages.**
- **One database ownership read:** check candidate ownership as a group rather
  than one query per each of the eight local index candidates.
- **Adaptive smartphone lookup:** exit the query fallback sequence only when
  two distinct successful, nonpartial searches independently return the **same
  one** full-identity, conflict-free exact URL. No clear answer, ambiguity, or
  partial search: keep exploring the remaining queries. Multiple exact URLs
  always go to manual review.
- **Faster job queue:** drain the next task after 100 ms rather than waiting for
  the one-second idle poll. The worker still runs one job at a time.
- **Unchanged safeguards:** 403/429 responses pause the job, only confirmed
  links are polled for updated prices, no auto-writing site or 1C prices.

### How to evaluate speed

Run the same selection of 100 in-stock 1C items on a **test instance**, compare
wall-clock time, confirmed matches, manual reviews, technical errors, and 05.ru
requests against the previous version. A short-lived cache makes later runs
faster, so cold-start and warm-start times must be measured separately.
This change was tested with automated stubs, not validated on the live stores.

## Простой мониторинг смартфонов: 1С → TEXHORU → 05.ru

### Что видит сотрудник

В админке **Мониторинг цен**:
- сверху количество смартфонов с доступным остатком из 1С;
- кнопки **Найти совпадения** и **Применить цены в разделе**;
- ниже — иерархия настоящих категорий 1С, открывающаяся по папкам;
- внутри категории — компактные карточки своих товаров: название, остаток, цена сайта, актуальная цена 05.ru, статус;
- некорректные связи — под кнопкой «Проверить», не в общем потоке. Остальные инструменты спрятаны.

### Появление на сайте

Товары добавляются и обновляются **действующим входящим обменом 1С** (`POST /api/integrations/1c/catalog`, ключ `ONE_C_API_KEY`), а не вручную в мониторинге. Для импортированных из 1С категорий смартфонов публичный каталог скрывает позиции, у которых доступный остаток (`stockQty - reservedQty`) равен нулю. После следующей выгрузки с положительным остатком товар снова виден на сайте, тот же `oneCId` и ID сохраняются. Прочие виды товаров и вся история остаются в базе.

**Важно:** внешний прямой обмен с конкретной рабочей 1С УТ 10.3 должен быть настроен отдельно. Этот PR не может сам открыть чужую базу 1С; он использует уже существующий API-контракт.

### Поиск совпадений

Кнопка запускает `MATCH_1C` только для **смартфонов с доступным остатком** в выбранной категории, с подгруппами. Поиск идёт напрямую через работающую `05.ru/search/?q=...`. Разделы с другими товарами и смартфоны с нулевым остатком исключаются. Очередь сохраняется между перезапусками.

### Одно подтверждение для цен

1. Программа предварительно собирает только подтверждённые связи с 05.ru, для которых проверка успешна за последние 24 часа, конкурент в наличии, совпадают контрольные отпечатки и цена не ниже известной себестоимости.
2. **Применить цены в разделе** показывает число изменяемых и пропускаемых позиций, число товаров без себестоимости и число больших изменений. Правило текущего проекта — **05.ru минус 500 ₽**.
3. Только после явного подтверждения сервер повторно проверяет тот же набор внутри транзакции и обновляет цены на сайте. Если изменилось хотя бы одно значение между просмотром и записью — **вся операция отменяется**. Изменения фиксируются в аудите.
4. В 1С цена передаётся только тем товарам, у которых ранее был включён `priceSyncEnabled` и настроен обмен. Для остальных обновляется цена сайта; следующая выгрузка 1С может перезаписать её, как и при прежнем одиночном применении.
5. Спорные, неподтверждённые, неактуальные, недоступные и без допустимой себестоимости позиции не меняются. При неизвестной себестоимости либо изменении более 10% пользователь получает отдельное явное предупреждение.

Текущий импорт цен из CSV, ручные ссылки, настройки расписания и история в базе не удалены; упрощённый рабочий экран больше не заставляет сотрудника проходить через них.

### Контрольный тест на рабочем компьютере

- Убедиться, что все смартфоны с доступным остатком появились в нужных папках; скрытые при нуле не исчезли из админки.
- Запустить поиск для одной небольшой категории, дождаться результатов.
- Открыть предварительный просмотр массовых изменений и проверить сумму и количество товаров. Для реального бизнеса сначала применить к тестовой категории, а не ко всему ассортименту.
- Проверить сайт и логи аудита, затем расширить охват.

CI тестирует API, запросы и атомарность на тестовой SQLite базе. Он не подменяет подключение к настоящей УТ 10.3 и контрольный запуск на твоей установке TEXHORU.

## Новый каталог TEXHORU — навигация по папкам и популярные iPhone

### Как работает

**Админка → Товары**: вместо раскрытого длинного списка 1С пользователь видит только текущий уровень дерева. Слева — название текущей папки, кнопка назад и её непосредственные дети. Справа — хлебные крошки и карточки подгрупп. Например: **МОБИЛЬНАЯ СВЯЗЬ → Смартфоны → Apple → iPhone 17 Pro / iPhone 17 Pro Max**. Внутри модели — реальные SKU. Переходы анимированы, поддерживаются клавиатура и мобильный экран.

**Витрина → Каталог**: та же логика по уровням; переход в раздел показывает заголовок, описание, подкатегории. На последнем уровне показываются товары. Поиск по всему каталогу остаётся независимым от категории. Категории, созданные из 1С, не переименовываются: названия линеек iPhone/Xiaomi/Galaxy — **виртуальные полки интерфейса**, не новые записи в базе, поэтому не затрагивают остатки, GUID, SEO-адрес товара и связи 05.ru.

**Главная**: до 10 реальных активных iPhone с положительным доступным остатком, выбираемых из API. На большом экране — 5 карточек в ряд, 2 ряда. В выборе соблюдается разнообразие: iPhone 17 Pro Max / Pro / базовая модель, затем другие поколения из наличия. Цена и остаток — только текущие данные TEXHORU, не копии из 05.ru.

### Фото товаров

Приоритет отдан собственным фотографиям, ранее загруженным в карточку. Если 1С прислала пустое фото или базовую заглушку, для линейки iPhone 17 используется один из **пяти специально нарисованных прозрачных SVG-вырезов** (оранжевый, синий, белый, зелёный, тёмный). Эти изображения локальные, быстро загружаются, без внешних сервисов и hotlink. Для старых поколений прежняя заглушка не заменяется чужим устройством.

Автоматическое копирование PNG с 05.ru не включено: прямой доступ к его медиа из среды разработки ограничен, а для коммерческого повторного использования чужих фото необходимо иметь разрешение правообладателя. Можно заменить SVG на разрешённые оригинальные PNG в `public/products/` и подключить их через обычное поле `image` товара в админке.

### Установка

Изменения затрагивают фронтенд и статические SVG, не добавляют миграции БД и не переименовывают папки 1С. Установить актуальный `main` через обычный способ обновления TEXHORU, сохранив БД, файлы и секреты. Перезапустить фронтенд и очистить кеш браузера. Проверить путь через **Товары → Мобильная связь → Смартфоны → Apple → iPhone 17 Pro** и главную с двумя рядами популярных моделей.
