# Простой мониторинг смартфонов: 1С → TEXHORU → 05.ru

## Что видит сотрудник

В админке **Мониторинг цен**:
- сверху количество смартфонов с доступным остатком из 1С;
- кнопки **Найти совпадения** и **Применить цены в разделе**;
- ниже — иерархия настоящих категорий 1С, открывающаяся по папкам;
- внутри категории — компактные карточки своих товаров: название, остаток, цена сайта, актуальная цена 05.ru, статус;
- некорректные связи — под кнопкой «Проверить», не в общем потоке. Остальные инструменты спрятаны.

## Появление на сайте

Товары добавляются и обновляются **действующим входящим обменом 1С** (`POST /api/integrations/1c/catalog`, ключ `ONE_C_API_KEY`), а не вручную в мониторинге. Для импортированных из 1С категорий смартфонов публичный каталог скрывает позиции, у которых доступный остаток (`stockQty - reservedQty`) равен нулю. После следующей выгрузки с положительным остатком товар снова виден на сайте, тот же `oneCId` и ID сохраняются. Прочие виды товаров и вся история остаются в базе.

**Важно:** внешний прямой обмен с конкретной рабочей 1С УТ 10.3 должен быть настроен отдельно. Этот PR не может сам открыть чужую базу 1С; он использует уже существующий API-контракт.

## Поиск совпадений

Кнопка запускает `MATCH_1C` только для **смартфонов с доступным остатком** в выбранной категории, с подгруппами. Поиск идёт напрямую через работающую `05.ru/search/?q=...`. Разделы с другими товарами и смартфоны с нулевым остатком исключаются. Очередь сохраняется между перезапусками.

## Одно подтверждение для цен

1. Программа предварительно собирает только подтверждённые связи с 05.ru, для которых проверка успешна за последние 24 часа, конкурент в наличии, совпадают контрольные отпечатки и цена не ниже известной себестоимости.
2. **Применить цены в разделе** показывает число изменяемых и пропускаемых позиций, число товаров без себестоимости и число больших изменений. Правило текущего проекта — **05.ru минус 500 ₽**.
3. Только после явного подтверждения сервер повторно проверяет тот же набор внутри транзакции и обновляет цены на сайте. Если изменилось хотя бы одно значение между просмотром и записью — **вся операция отменяется**. Изменения фиксируются в аудите.
4. В 1С цена передаётся только тем товарам, у которых ранее был включён `priceSyncEnabled` и настроен обмен. Для остальных обновляется цена сайта; следующая выгрузка 1С может перезаписать её, как и при прежнем одиночном применении.
5. Спорные, неподтверждённые, неактуальные, недоступные и без допустимой себестоимости позиции не меняются. При неизвестной себестоимости либо изменении более 10% пользователь получает отдельное явное предупреждение.

Текущий импорт цен из CSV, ручные ссылки, настройки расписания и история в базе не удалены; упрощённый рабочий экран больше не заставляет сотрудника проходить через них.

## Контрольный тест на рабочем компьютере

- Убедиться, что все смартфоны с доступным остатком появились в нужных папках; скрытые при нуле не исчезли из админки.
- Запустить поиск для одной небольшой категории, дождаться результатов.
- Открыть предварительный просмотр массовых изменений и проверить сумму и количество товаров. Для реального бизнеса сначала применить к тестовой категории, а не ко всему ассортименту.
- Проверить сайт и логи аудита, затем расширить охват.

CI тестирует API, запросы и атомарность на тестовой SQLite базе. Он не подменяет подключение к настоящей УТ 10.3 и контрольный запуск на твоей установке TEXHORU.
