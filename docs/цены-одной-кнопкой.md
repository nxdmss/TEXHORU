# Обновление цен одной кнопкой

Схема демонстрации прежняя: TEXHORU и ngrok запущены на компьютере демонстратора, агент — на компьютере с TEST 1С. На экране «Цены» теперь одно действие **Обновить все цены**.

## Как пользоваться

1. Открой **Управление магазином → Цены** и нажми **Обновить все цены**. Кнопка запускает проверку карточек 05.ru и подготовку передачи для активных товаров, загруженных из 1С.
2. Для части каталога раскрой **Выбрать товары**: выбери раздел, введи название или отметь позиции. Основная кнопка станет **Обновить выбранные (N)**. «Снять выбор» оставляет ноль выбранных и отключает запуск; «Все товары» явно возвращает полный каталог.
3. Ход проверки виден одной строкой. **Что обновилось** раскрывает результат по каждому товару и причины пропуска. **Обновлено** означает подтверждение записи в 1С, после которого публикуется цена сайта. Само попадание в очередь успехом не считается.

Выбор разрешений 1С больше не является обязательным ручным шагом. Процесс готовит только подходящие проверенные товары группами до 30. Неиспользуемые разрешения, случайно занятые чехлами и стёклами, освобождаются автоматически. Существующие незавершённые передачи сохраняются. Новая группа передаётся только после завершения предыдущей очереди и сеанса агента, поэтому его старый снимок разрешений не используется для новой группы.

## Что делает процесс

Он сохраняет выбранный список товаров, использует существующий поиск точных совпадений и перечитывает реальные карточки перед подготовкой изменения. Проверяет модель, память, цвет, SIM, состояние, наличие, свежесть цены. В TEST ограничение изменения 10% временно отключено. Цена — подтверждённая цена 05.ru минус 100 ₽. Неоднозначность и отсутствие карточки остаются причинами пропуска: одинакового названия недостаточно для обещания совпадения.

Недавние доказанные «нет совпадений» не запускают одинаковый поиск аксессуаров при каждом обновлении всего каталога. Через 24 часа такая запись перестаёт блокировать повторный поиск; явный выбор товара также означает повторную проверку. Старые данные не называются свежими при сетевой ошибке.

Запуск сохраняется в базе. Закрытие браузера не отменяет обновление; повторное нажатие во время работы возвращает текущий процесс. После перезапуска сервера работа продолжается из сохранённого состояния. При недоступной 1С подготовленные изменения ждут в очереди. Ошибка агента не превращается в подтверждение.

**Остановить подготовку** прекращает оставшиеся проверки и подготовку. Уже переданные в очередь изменения продолжают обмен: их квитанции могут прийти после остановки.

## Что скрыто

- **Выбрать товары** — разделы, поиск и индивидуальный выбор.
- **Что обновилось** — результат, фильтр и причины по каждой позиции.
- **Связи с 05.ru и дополнительные проверки** — ручная работа с неоднозначными карточками. Пока блок закрыт, его дополнительные запросы не выполняются.
- **Как обновляются цены** — правило расчёта.
- В **Обмен с 1С** история, разрешения и журнал находятся в свёрнутых блоках.

## Однократная проверка подключения

До первого показа убедись, что агент открывает настоящий файл EPF. Текст модуля с расширением `.epf` обработкой не является. Новый агент выявляет такой файл и останавливает запуск с понятной ошибкой до открытия 1С. Это не заменяет проверку настоящего контейнера самой платформой.

В Конфигураторе открой существующую внешнюю обработку EPF, замени модуль обычной основной формы, проверь синтаксис и сохрани **внешнюю обработку**, активировав окно её объекта. Для проверки открой сохранённый EPF в TEST вручную: без параметра агента очередь не обрабатывается. Затем обнови агент через `onec/agent/UPDATE-WINDOWS.cmd` под той же учётной записью Windows. Пустая очередь сама по себе не проверяет открытие EPF — для приёмки нужен один реальный выбранный товар и его квитанция.

После обычного выключения и включения компьютера агент работает после входа в Windows. Задача, отключённая через `Disable-ScheduledTask`, остаётся отключённой до явного включения.

## Проверки для разработчика

```bash
npm run build:all
npm --prefix server run test:monitor
node --test tests/project-readiness.test.mjs tests/catalog-groups.test.mjs tests/demo-launcher.test.mjs
node tests/price-demo.browser.mjs
```

Браузерный тест использует отдельную SQLite и подставные ответы workflow для проверки all/selected, свёрнутых блоков, polling, подтверждённого статуса и мобильной ширины. Реальные транзакции, пакетирование, очередь и квитанции проверяются серверными тестами. Тесты не обращаются к реальной 05.ru или рабочей 1С.
