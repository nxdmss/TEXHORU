# Управление каталогом 1С из админки TEXHORU

Для УТ 10.3 на Windows и платформы 1С 8.3 со штатным COM-коннектором. Панель: **Управление → Обмен с 1С → Каталог под управлением**. Отдельная EPF для этой выгрузки не нужна: агент читает каталог через COM. Прежняя форма остаётся отдельным способом обмена; не запускайте их одновременно. Старый TEST-агент для этой задачи не используется.

Это чтение каталога, групп, рублёвых розничных/закупочных цен и остатков. Агент не получает произвольный код с сайта, не выполняет SQL и не проводит документы в 1С. Применение розничных цен остаётся отдельным механизмом основной обработки. Это не копия всей программы 1С в браузере.

## 1. Обновить сайт

В PowerShell своего компьютера:

```powershell
ssh -i "$env:USERPROFILE\.ssh\texhoru_yandex" ubuntu@84.201.148.192
```

На сервере:

```bash
sudo texhoru update
sudo nano /etc/texhoru/app.env
```

Укажите/проверьте эти параметры (остальные, включая почту, сохраняйте):

```dotenv
ONE_C_BASE_KIND=PRODUCTION
ONE_C_PRODUCTION_BASE_ID=texhoru-main-ut103
ONE_C_TEST_PRICE_SYNC_ENABLED=false
```

`ONE_C_API_KEY` должен быть задан: это существующий секрет обмена, а не пароль сайта/почты/1С. Введите его локально при установке агента; в чат присылать его не нужно. Флаг `ONE_C_PRODUCTION_PRICE_SYNC_ENABLED` для чтения каталога не нужен: его существующее значение не меняйте. При первом переключении с TEST на PRODUCTION старые разрешения записи цен сбрасываются по правилам основного профиля; база сайта не очищается.

В nano: **Ctrl+O → Enter → Ctrl+X**. Применить настройки:

```bash
cd /opt/texhoru
sudo docker compose --env-file /etc/texhoru/compose.env -f deploy/cloud/compose.yaml up -d --force-recreate --wait app
```

Обычный restart не перечитывает env. Новые таблицы создаются существующим шагом обновления схемы при старте контейнера.

## 2. Подготовить компьютер с 1С

1. Откройте **1С:Предприятие**, выберите пользователя для обмена с разрешением внешнего COM-соединения и чтения номенклатуры, типов цен, цен и остатков. Полные права и запись документов этому агенту не нужны.
2. В окне запуска 1С выберите свою базу → **Изменить**. Узнайте путь к файловой базе либо сервер и имя серверной базы. Ничего там не меняйте.
3. Проверьте наличие компонента **COM-соединение** в установленной платформе 1С. Он должен соответствовать версии платформы базы и разрядности PowerShell. Может требоваться отдельная лицензия 1С для внешнего соединения — зависит от лицензирования установки.
4. Если COM не зарегистрирован, в командной строке **от администратора** выполните команду с реальным путём своей платформы:

```cmd
regsvr32 "C:\Program Files\1cv8\8.3.ВАША_ВЕРСИЯ\bin\comcntr.dll"
```

Для 32-битной платформы укажите её папку (обычно `Program Files (x86)`), используйте `%SystemRoot%\SysWOW64\regsvr32.exe`, а установщик ниже запускайте через `INSTALL-32.cmd`. Для 64-битной — `INSTALL.cmd`. Не копируйте буквальное `ВАША_ВЕРСИЯ`: это пример места для номера вашей установленной платформы.

## 3. Установить агент один раз

1. [Скачайте ZIP проекта](https://github.com/nxdmss/TEXHORU/archive/refs/heads/main.zip) и распакуйте.
2. Откройте папку `TEXHORU-main\onec\catalog-agent`.
3. Запустите `INSTALL.cmd` (или `INSTALL-32.cmd` для 32-битного COM).
4. Ответьте на вопросы установщика:
   - **Домен:** адрес вашего магазина без `https://` и без `/` (ровно домен из адресной строки).
   - **Идентификатор базы:** `texhoru-main-ut103`, если на сервере указали именно его.
   - **Ключ:** значение `ONE_C_API_KEY` с сервера, ввод скрыт.
   - **Строка подключения:** для файловой базы `File="C:\путь\к\базе";Usr="ОбменСайта";Pwd="пароль";`, для серверной `Srvr="сервер";Ref="имя_базы";Usr="ОбменСайта";Pwd="пароль";`. Подставьте реальные данные локально, ввод скрыт. При аутентификации Windows допустимо опустить `Usr`/`Pwd`, если пользователь Windows имеет доступ к этой базе.
   - **Розничный тип:** Enter для `Розничная`.
   - **Закупочный тип:** Enter для `Закупочная`.
5. Установщик создаст Windows-задачу **TEXHORU Catalog Agent** и запустит первый опрос. Настройки сохраняются в `%LOCALAPPDATA%\TEXHORU\CatalogAgent`; ключ и строка подключения зашифрованы DPAPI для текущего пользователя Windows. Задача работает от этого же пользователя с обычными правами.

Компьютер должен быть включён, пользователь Windows — оставаться в системе. Заблокировать экран можно; выходить из учётной записи Windows нельзя. Развёртывание как служба без входа пользователя в эту версию не входит. Открытый интерфейс 1С не требуется. Обновление файлов агента — повторный запуск установщика из новой распакованной версии.

## 4. Работать с сайта

1. Зайдите в админку → **Обмен с 1С**. В течение минуты агент появится на связи и начнёт читать список групп.
2. Дождитесь завершения задания «Обновление групп». Папки открываются нажатием на название; «Все группы» возвращает к корню. Поиск работает по всей базе, список выдаётся страницами по 100 групп.
3. Для первой проверки отметьте небольшую группу → **Загрузить выбранные**. Выгружаются также все подгруппы. Можно отметить до 20 групп за раз или нажать **Загрузить весь каталог**.
4. Смотрите задания справа: очередь, загрузка, готово, ошибка, количество просмотренных/принятых/неизменённых/дублей. Статус группы отражает последнее задание, запущенное именно для неё; общая загрузка всего каталога видна отдельным заданием. Время последнего получения данных хранится у группы и после ухода старого задания из списка. Получение части товаров не означает завершение всей группы — завершение подтверждает статус задания. Это не полный поштучный журнал всех товаров и не гарантия неизменности базы с момента последней загрузки.
5. **Пауза → Продолжить** сохраняет курсор. **Отменить** оставляет уже принятые товары. При ошибке исправьте подключение/права/данные, затем нажмите **Повторить**. Если файл базы был заменён другой базой, задайте новый идентификатор профиля; не продолжайте старый курсор.
6. При следующих запусках выбирайте **Только изменения**. Группа просматривается заново, но полные карточки передаются только при изменениях подписи данных. В этой версии автоматическое обновление товаров по расписанию не включено: запуск выполняется кнопкой на сайте. Группы автоматически перечитываются раз в 5 минут после завершения предыдущего успешного чтения, также есть кнопка «Обновить группы».

Агент опрашивает задания раз в минуту, при работе посылает пакеты с паузой 1 секунда. UI опрашивает прогресс раз в 5 секунд только на открытой вкладке. Изменения в середине прохода могут попасть в следующий проход: транзакционная копия всей базы не снимается.

## Ограничения и восстановление

- В памяти одновременно до 50 товаров/групп, пакет до 512 КБ. Фото, вложения и документы не передаются. Структура и прогресс сохраняются на сервере, при обрыве повторный пакет не удваивает товары/счётчики. Хэш DELTA занимает одну запись на товар, история завершённых заданий ограничена 1000 записями. Отсутствие товара в частичной группе ничего не удаляет; пометка удаления архивирует переданную карточку.
- Количество у папки — число непомеченных товаров непосредственно в ней, без подгрупп. Прогресс — реальные счётчики, без выдуманного процента от неизвестного общего количества.
- Как в основном BSL-модуле, поддерживаются рубли, целые цены и штучные остатки базовой номенклатуры без характеристик. Характеристики, упаковки, другие валюты и изменённые метаданные требуют адаптации. До массового запуска проверьте на небольшой группе цены/остатки относительно вашей УТ 10.3. При неопределённой закупочной отправляется `null`; это блокирует автоматическое изменение розничной на сайте.
- `COM_CONNECT`: проверьте разрядность, регистрацию `comcntr.dll`, лицензию, строку подключения, пользователя и разрешение внешнего соединения. `CATALOG_READ`: проверьте имена типов цен, права чтения, валюту и соответствие регистров УТ 10.3. `HTTP` в локальном журнале: проверьте домен, интернет, ключ и совпадение профиля базы. Исходные ошибки провайдера с потенциальными паролями не пишутся в журнал.
- Журнал: `%LOCALAPPDATA%\TEXHORU\CatalogAgent\catalog-agent.log`, ротация по 1 МБ. В Планировщике заданий можно вручную запустить **TEXHORU Catalog Agent** для проверки.
- Если старый ручной сеанс занял обмен, завершите/отмените его в блоке «Выгрузка через прежнюю обработку 1С». Одновременно выполняется только один сеанс каталога. Приостановленный или ошибочный активный сеанс сначала продолжите, повторите или отмените.
- Удаление агента: Планировщик заданий → **TEXHORU Catalog Agent → Отключить**, затем **Удалить**. После остановки можно удалить его папку из `%LOCALAPPDATA%\TEXHORU`.

Платформы 1С в среде разработки нет: COM-адаптер нужно проверить на вашей установленной УТ. Серверные HTTP-проверки и браузерные проверки панели не заменяют эту проверку.
