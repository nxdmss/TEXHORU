# Как предлагать изменения в TEXHORU

Спасибо за помощь с проектом. Здесь простые правила, чтобы работа разных программистов не ломала магазин.

## Перед работой

1. Прочитай [памятку по проекту](docs/передача-разработчику.md).
2. Создай отдельную ветку от `main`.
3. Не меняй сразу весь проект: один понятный набор изменений проще проверить.
4. Не добавляй в GitHub базу магазина, ключи, пароли и файлы `.env.local`.

## Перед отправкой

```bash
npm run build:all
npm --prefix server run test:monitor
```

Если тесты не прошли, укажи это в описании и не объединяй изменения.

## Описание изменений

Напиши обычными словами:

- **Что изменилось.** Например: «Упростил выбор товаров при обновлении цен».
- **Где проверить.** Например: «Админка → Цены → Выбрать товары».
- **Что не трогали.** Например: «Обмен с рабочей 1С не менялся».
- **Что осталось.** Если нужны настройки или проверка на Windows, укажи прямо.

Управление магазином должно быть понятным без знания исходного кода. Подписи кнопок и сообщения об ошибках пиши по-русски. Технические имена внутри программы можно оставлять, если они нужны для совместимости.

**Главное:** проверка цен может быть автоматической; изменение розничной цены — только после выбора сотрудника. Продуктивную 1С не использовать для испытаний.
